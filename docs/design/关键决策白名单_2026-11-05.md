# 关键决策白名单（Decision Whitelist）

|项|内容|
|-|-|
|版本|v1.0|
|日期|2026-11-05|
|定位|账本的**入账规则**：定义什么算一条 `decision`，从而定义所有评分与责任的分母|
|上游依赖|run 边界 = task（见 §1）|
|下游消费|决策证据链、不确定性标记、策略门、replay、Score Aggregator|
|平台依据|openJiuwen `0.1.20.post1`：`before_tool_call` / `before_model_call` / `on_stop`|

---

## 0. 为什么需要一张白名单

账本的原子单位是 `decision`。不给出「什么算决策」的确定性定义，会同时踩两个坑：

| 坑 | 表现 | 后果 |
| - | - | - |
| 记太多 | 每个工具调用都入账 | 账本退化为日志，分母被稀释，分数失去区分度 |
| 记太少 | 真正担责的那一步没记 | 事后查不出、replay 拼不出、责任落不到人 |

**白名单不是功能清单，是分母定义。** 它一旦定下，后续所有比率型指标（含 ARS 的 L/R/D/F、证据完整度）的分母就都锁定了，改动即口径变更，需走版本号。

---

## 1. 前置：run 边界 = task

`decision` 挂在 run 上，run 边界不定，入账规则无从谈起。

| 层 | 是否 run 边界 | 理由 |
| - | - | - |
| Session | ❌ 否 | 跨天，混多个无关任务，生命周期由客户端决定 |
| **Task（一次用户/上游请求）** | ✅ **是** | 有始有终，可重放、可归属、可中断恢复 |
| Span tree | ❌ 否 | run 的内部结构，一个 run 内数十至数百个 span |

开：收到任务的那一刻（`before_prompt`）。
闭（先到为准）：① 不再发起新工具调用且产出终稿；② 进入 `wait_user` 中断；③ 超时/异常终止。

| 易混情况 | 处理 |
| - | - |
| 并行工具调用 | 同一 run 内的并发 span |
| 子 agent 委派 | 默认归父 run；仅 `detached` 另起 run 并写 `parent_run_id` |
| 重试 | 同 run 内 retry span，`run_id` 不变 |
| 人机中断后 resume | 同 run 继续，`run_id` 不变，`segment` +1 |
| 挂起后用户发新消息 | 新 run，`trigger=query` |

硬约束：**一个 run 至少含 1 个 decision**。不含 decision 的 span tree 不进账本，否则纯 IO / 心跳也会成为审计对象。

---

## 2. 判定规则

一个事件算 `decision`，当且仅当满足**任意一条**：

| # | 判定 | 含义 |
| - | - | - |
| R1 | 改变了 agent 之外的状态 | 写文件、改库、发消息、调写接口 |
| R2 | 错了撤不回 | 删除、push、发布、对外发送 |
| R3 | 产生了不可重算的分叉 | 转人工、中止、换目标/换模型 |

**R3 必须收紧**：「读完文件决定读下一个」**不算**分叉——重算一遍会得到同样结果。只有「重算也回不去的分叉」才算。

---

## 3. 白名单（入账）

| # | decision_class | 事件 | 捕获钩子 | 命中规则 |
| - | - | - | - | - |
| 1 | `file_write` | 写 / 改文件（`write_file`、`edit_file`） | `before_tool` | R1 |
| 2 | `file_delete` | 删除 / 移动 / 覆盖 | `before_tool` | R2 |
| 3 | `exec` | 执行命令 / 跑代码 | `before_tool` | R1 |
| 4 | `network_write` | 对外写请求（POST/PUT/DELETE、发邮件、发消息、提交表单） | `before_tool` | R2 |
| 5 | `vcs_publish` | 提交代码 / push / 发布 | `before_tool` | R2 |
| 6 | `policy_decision` | 策略命中 `DENY` / `ASK` / `REWRITE` | `before_tool` 返回 | R1 |
| 7 | `human_ack` | 用户在 `ASK` 上的答复 | 中断恢复 | R1（人的签字） |
| 8 | `delegate` | 委派子 agent（尤其 `detached`） | `before_tool` | R3 |
| 9 | `abort` | 显式中止（`force_finish` / 用户打断） | `before_model_call` / `on_stop` | R3 |
| 10 | `run_close` | run 关闭（写入 `close_reason`） | `on_stop` | R3 |
| 11 | `final_claim` | 终稿中产出的 claim | run 收尾 | 法证对象 |

第 6 条特别说明：**干预本身要留痕**。策略门做出 `DENY` 却不记录，等于系统里「跳过验证这件事不可见」——这正是原 PRD §1.2 三堵墙中的第二堵。

第 11 条中的 claim 定义沿用既有口径：**可判定断言 = 主体 + 指标 + 值 + 条件**四要素。claim 不是决策的替代品，而是决策链末端的产出物。

## 4. 黑名单（只记 span，不入账）

| 类别 | 具体 |
| - | - |
| 只读工具 | `read`、`grep`、`glob`、列目录 |
| 只读网络 | GET、网页抓取 |
| 模型内部 | embedding、rerank、token 计数与成本记账 |
| 过程事件 | 心跳、进度事件、lifecycle events |
| 上下文处理 | 压缩、摘要、memory 装配 |
| 重试 | 参数未变的重试 |
| 并发冗余 | 并行的第二个同类只读调用 |

这些**照样写 OTel span，但不写账本**。区别是：

- span 回答「发生过什么」——可丢弃，可采样，受 retention 清理；
- decision 回答「谁要为它负责」——不可变，可重放，可被第三方复算。

---

## 5. 实现约束

判定必须是**确定性查表**，不得由 LLM 判断「这个重不重要」：

```text
decision_class = POLICY[tool_name][action_type]
action_type    ∈ {read, write, exec, network_read, network_write, delegate}
```

- 输入只有：工具名 + 动作类型（必要时加路径、域名等可规则化字段）。
- 输出：`decision_class` 或 `None`。
- 禁止：模型参与分类、按内容语义打分、模糊匹配。

**依据**：账本的可复算性上限 = 判定函数的确定性。判定一旦含模型判断，同一输入两次跑可能给出不同的分母，比率型指标随即失效。

落成契约即一个枚举：

```python
DecisionClass = Literal[
    "file_write", "file_delete", "exec", "network_write", "vcs_publish",
    "policy_decision", "human_ack", "delegate", "abort", "run_close", "final_claim",
]
```

## 6. 自检指标

除了定义「记什么」，这张表顺带提供一个**策略健康度**指标：

| 指标 | 正常区间 | 偏离含义 |
| - | - | - |
| `decision / tool_span` | **0.10 – 0.30** | > 0.3：判定规则过宽，账本在退化为日志；< 0.05：漏记，多半漏了 `network_write` |
| 单 run decision 数 | **3 – 8**（典型） | 40+ 条：规则过宽；高风险 run 仅 1 条：漏记 |
| `run_close` 覆盖率 | 100% | 有 run 无 close，说明边界闭合逻辑有洞 |

这三个数不进入对外评分，只作为工程侧的口径校验项。

## 7. 与观测层的关系

| 项 | 归属 |
| - | - |
| span 树结构、跨进程串联（`traceparent`） | OTel |
| 决策语义（claim、locator、策略命中、不确定性标记） | 账本 |
| OTel 中的决策痕迹 | 仅存**引用 id**，不存语义 |

理由：openJiuwen 的 `TraceFileExporter` 按天切文件 `traces-YYYY-MM-DD.jsonl` 并带 `retention_days` 过期清理，本质是可丢弃观测数据；账本要求不可变、可重放、可复算，两者不能是同一份存储。
