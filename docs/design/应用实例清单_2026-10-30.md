## U1 投研日报结论复核

**场景**：每天 08:30 生成持仓日报，20 条结论（PE/PB 比较、行业均值、仓位提示），对外发送前需合规签字。

**对象**：数值型 claim；证据 = 行情 CSV + 行业均值表 + 接口返回。

**目标**
- 业务：签字人 3 分钟内判断"哪几条能签、哪几条要补"；
- 产品：把不可复核的结论从"没人知道"变成"记在账上"。

**路径**
1. S0 编译 10 条日报规则 → 3 条可编译，7 条失败（4 主观 / 2 缺字段 / 1 依赖 LLM）；
2. S1 为 3 条可编译规则建检查 + 每条 3 个 fixture（`n_checks = 10`）；
3. **ARS_d**：只算 C = 0.30 (< 0.5) → **设计预警**（低分提示 + `design_ack` 确认继续，不阻断）；
4. S2 跑一次 → 20 条 claim、约 30 次工具调用；
5. S3 证据包，locator 精确到 `file:row:field`，9 条缺精确定位；
6. S4 对 20 条全量复算 → 8 verified / 3 refuted / 9 indeterminate；
7. **ARS_r**：L 9/20 / R 8/20 / D 6/10 / F 15/20，合成 **ARS 47（D 档）**；
8. S6 发布闸拦截 + 出改造方案。

**适配**
- 数值可回源、日频重复、有明确签字人；
- 数据源稳定且有版本。

**不适配**
- 结论是"建议买入""看好后市"这类不可判命题；
- 依赖未公开/内幕数据（合规红线）；
- 单次性报告（没有重复运行，F 项无意义）。

**量化质检**

| 指标 | 线 | 方法 |
|---|---|---|
| 可定位率 | ≥0.85 | 抽 50 条人工核 |
| 复算一致率 | ≥0.90 | 第三方按包重算 |
| 错误召回 | 100% | 注入 3 个错误值，必须全被抓 |
| 误报率 | ≤10% | 50 条人工复核 |
| ARS 复算差异 | 0 | 独立脚本重算 |
| 端到端时延 | p95 ≤20s | 200 claim |
| 单条成本 | ≤6 CU | 账单统计 |

## U2 代码评审意见可追溯

**场景**：代码评审组对 3 个文件出评审意见（12 条），意见需能指到具体行。

**对象**：代码行级 claim；证据 = 源文件 + 规范规则。

**目标**
- 业务：评审意见从"我觉得"变成"第 42–44 行违反 X 规范"；
- 产品：证明同一套链路换证据形态也能跑（通用性）。

**路径**
1. S0 编译 8 条规范规则 → 6 条可编译（阈值类最容易编）；
2. S1 建 `line_lookup` + `rule_replay` 检查；
3. S2 跑评审 → 12 条意见；
4. S3 locator = `file:line` 或 `file:line:line`；
5. S4 复核行号是否存在、规范是否命中；
6. **ARS**：L 应显著高于 U1（因为行号更容易精确）；
7. S6 出报告。

**适配**
- 规则可判定（命名、圈复杂度、禁止 API）；
- 源文件可读且版本明确。

**不适配**
- 架构/设计评审（主观，编不出）；
- 跨文件影响分析（超出单文件定位）；
- 动态行为问题（需要运行，不是静态）。

**量化质检**

| 指标 | 线 | 方法 |
|---|---|---|
| 行号准确率 | ≥95% | 抽 50 条对源码 |
| 意见可定位率 | 100% | 每条都有 locator |
| 误报率 | ≤15% | 人工复核 |
| 检查 fixture 通过 | 100% | `make test-checks` |
| 单条成本 | ≤2 CU | 账单 |

## U3 Skill 上架体检

**场景**：Hub 运营对候选 Skill 做上架前体检，决定放行或退回。

**对象**：Skill 包（`SKILL.md` + `roles/` + `workflow.md` + `bind.md`）。

**目标**：把"跑分不错"换成"可审计性够不够"，并给出退回理由。

**路径**
1. 批量 S0 编译该 Skill 的全部判定条款；
2. 抽样跑 3 次（不同输入画像），收集 claim；
3. 计算 ARS_d 与 ARS_r；
4. 生成一页报告（五维 + 三条扣分项 + 报价）；
5. 放行 / 退回改造。

**适配**：规则成文、有判定条款的 Skill。
**不适配**：纯创意生成类、无判定规则的 Skill（应输出 N/A）。

**量化质检**

| 指标 | 线 | 方法 |
|---|---|---|
| 双人评分一致 | κ ≥0.7 | 20 个 Skill 独立打分 |
| 评分可复算 | 差异 0 | 独立脚本 |
| 报告生成 | ≤10s/Skill | 计时 |
| 退回理由可执行 | 100% 带动作与报价 | 人工检查 |

## U4 采购尽调三选一

**场景**：企业要买一个"合同审查"类 Skill，三个候选，需选一个并说明理由。

**对象**：三个 Skill 在同一坐标下的 ARS。

**目标**：把"看起来都差不多"变成可比较的五维表 + 到 B 档的报价。

**路径**
1. 固定坐标（同一模型、同一数据画像）；
2. 三个 Skill 各跑 3 次；
3. 出对比表（五维 + 报价 + 风险提示）；
4. 给出建议：选 A（79 分）而非 B（61 分），因为 R 差 0.3。

**适配**：同类 Skill、可同坐标比较。
**不适配**：不同品类（合同审查 vs 代码评审不可比）；坐标不一致时不可比。

**量化质检**

| 指标 | 线 | 方法 |
|---|---|---|
| 坐标一致性 | 100% | 记录 model + data_profile |
| 分数可复现 | 差异 ≤1 分 | 重跑 3 次 |
| 对比表可读 | 3 人盲测均能说清差异 | 小样本测试 |

## U5 发布闸拦截与豁免

**场景**：6 个待发布版本，3 个应拦、3 个应放。

**对象**：release。

**目标**：证明闸门不是摆设——该拦的拦住，该放的放行。

**路径**
1. 对 6 个版本各算 ARS；
2. 低于 70 的拦截并给方案；达标的放行；
3. 允许人工豁免，但必须落 `waiver`（谁、何时、理由、有效期）；
4. 复核：豁免条目在面板上可查。

**适配**：有明确发布动作的团队。
**不适配**：没有发布节奏（无闸可装）。

**量化质检**

| 指标 | 线 | 方法 |
|---|---|---|
| 拦截准确 | 6/6 正确 | 混淆矩阵 |
| 漏拦 | 0 | 人工构造应拦样本 |
| 豁免留痕 | 100% | 抽查 |
| 拦截理由可执行 | 100% 带"差什么+多少钱" | 人工检查 |

## U6 一次性改造闭环（47 → 79）

**场景**：同一 Skill，改造前后各跑一次，看分数变化。

**对象**：规则集 + 两次运行的 claim 集。

**目标**：证明"分数会涨，且涨得可预测"。

**路径**
1. 测：ARS 47（D）；
2. 诊：L 9/20 缺 9 条精确定位；C 3/10 缺 4 条可编译规则；
3. 方：补定位 6.3 + 原地改写 4 条规则（含 4 check + 12 fixture）12.0 + 补字段 8.0 + 重跑检查 4.0 + 重跑过期证据 2.0 = 32.3，加 5% 缓冲 → **34 CU**，预测 **79**；
4. 行：原地改写规则、补 locator、补字段、重跑；
5. 测：L 18/20 / C 7/10 / R 16/20 / D 10/14 / F 17/20 → **ARS 79（B）**；
6. 语：新增失败样本入库。

**适配**：规则可改的 Skill。
**不适配**：规则由第三方提供且不可改；只能等新版本。

**量化质检**

| 指标 | 线 | 方法 |
|---|---|---|
| 预测兑现率 | ≥70% | \|实际-预测\|/预测 |
| CU 偏差 | ≤25% | 实际 vs 报价 |
| 语料增量 | ≥20 条 | 导出计数 |
| 分数复算 | 差异 0 | 独立脚本 |

## U7 合同条款缺失核查（软证据边界）

**场景**：20 份合同，核查是否含"争议解决""不可抗力"等 6 类条款。

**对象**：页级/段落级 claim；证据 = PDF 文本层。

**目标**：展示"软证据能做到什么程度"，并给出低分的诚实诊断。

**路径**
1. S0 编译 6 条条款规则 → 4 条可编译（"是否包含 X"可判）；
2. S3 locator 只能到页/段；
3. S4 `rule_replay`（文本命中）+ 人工抽检；
4. ARS 预期偏低（L 0.6 / C 0.4 / R 0.3 / D 0.5 / F 1.0 → 10+15+6+7.5+15 = 53.5 → **54 分，C 档**）。

**适配**：有文本层、条款可枚举。
**不适配**：扫描件（无文本层→直接 NO_LOCATOR）；需要理解条款实质（语义判断）。

**量化质检**

| 指标 | 线 | 方法 |
|---|---|---|
| 条款召回 | ≥95% | 20 份 × 6 类，人工对照 |
| 误报 | ≤10% | 抽 50 条 |
| 低分诊断正确 | ≥80% | 与人工判断一致性 |
| 扫描件处理 | 100% 输出 NO_LOCATOR | 构造 3 份扫描件 |

## U8 反例：会议纪要 / 创意文案

**场景**：用户拿一个"会议纪要提炼"或"文案生成"Skill 来问"能审吗"。

**对象**：无判定规则、无事实锚点。

**目标**：**主动劝退**——证明产品知道自己的边界。

**路径**
1. S0 编译 → 100% 失败（全部 `SUBJECTIVE_RULE`）；
2. 判定"不适用"（三条件任一成立：无可定位 claim / 规则 100% 不可编译 / 证据不可访问）；
3. 输出 **N/A + 原因**，不输出分数。

**关键设计**：不适用时**必须拒绝打分**。若硬给一个 30 分，产品就变成了"什么都能量"的假仪表。

**量化质检**

| 指标 | 线 | 方法 |
|---|---|---|
| N/A 判定正确 | 100% | 5 个反例全部拒评 |
| 原因可读 | 3 人盲测均理解 | 小样本 |
| 不静默失败 | 100% 有原因码 | 抽查 |

## 通用质检框架（四类检验）

| 类 | 测什么 | 方法 | 样本 |
|---|---|---|---|
| **正确性** | 结论对不对 | 注入已知错误 + 人工对照 | 3–5 个注入样本 / 50 条人工 |
| **一致性** | 换人/换机是否一样 | 双人评分 κ、独立脚本复算 | 20 个 Skill / 全量 |
| **有效性** | 改造是否真提升 | 前后对照 + 预测兑现率 | 1 个闭环 |
| **性能** | 是否可用 | 时延 p50/p95、CU/条 | 200 claim |

**每条线都必须能写进报告的一张表**：指标 / 线 / 实测 / 方法 / 样本量。没有样本量的指标不算指标。

## 选用建议

| 目的 | 用哪几个 |
|---|---|
| 3 分钟视频 | U1（走通）→ U6（提升）→ U5（拦截） |
| 技术报告 | U3、U4、U7（证明边界与生态价值） |
| 答辩防守 | U8（主动说"这类我们不接"） |
| 风险最小 | 若 U2 时间不够，砍成"1 个文件 + 3 条意见"，别砍 U5 |

一句话：**五个实例证明能做，一个实例证明不接——后者比前者更能建立信任。**

## 质检口径 v1.1 补充（2026-10-30）

以下三条对所有已适配实例生效，替代"声明即通过"的旧口径：

| # | 新增检查 | 线 | 适用 |
|---|---|---|---|
| Q1 | **locator 回源解析率** | ≥85%，且与声明精确率差 ≤0.15 | U1–U7 |
| Q2 | **PARTIAL 输出** | 样本 <10 时只报分项，不出总分 | U3、U7 |
| Q3 | **红队样本** | 10 个"形式合规"Skill 中 ≥8 个被标记 | U3、U6 |

> 任一实例若无法通过 Q1，其 ARS 只能报 `PARTIAL`，不得进闸门比较。
