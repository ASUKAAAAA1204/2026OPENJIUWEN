# 全链路 v2：以「审计就绪度」为主线的可信 / 可审计闭环

> 日期：2026-10-29
> 合并：`全链路装配与效率设计`、`PRD v1.1`、`主线\_审计就绪度ARS`
> 一句话：\*\*别人只有一条正向的验证链；我们补两条反向回路，并把"能不能被验证"变成整条链的闸门。\*\*

\---

## 1\. 总图

```
【四性】        可观测         可追溯         可问责        可验证（空位）
                  │              │              │              │
【生命周期】  设计 → 装配 → 运行 → 证据 → 判定 → 回执 → 决策 → 治理
                  ▲                                              │
                  │                                      ┌───────┘
                  └──────── Loop B：就绪度回流 ──────────┘

【谁做】     我们(主)  我们   平台    我们   借   参考   我们(主)  我们(主)
               │        │      │       │      │     │       │        │
【ARS 落点】  L·C主 ────C主──  D·F主 ─ R主 ── R ─── R ── 闸门 ── 语料累积
```

* **Loop A（验证回路，正向）**：规则 → 检查 → 证据 → 判定 → 回执。七篇论文都在这一段。
* **Loop B（就绪度回路，反向）**：ARS 扣分 → 改造方案 → 规则修订。**没人做，且唯一会复利。**
* **Loop C（经济回路，横切）**：CU 定价 → 改造路径成本 → 预算与闸门。让 B 可执行。

**主线 = Loop B；Loop A 是它的数据源；Loop C 是它的预算表。**

## 2\. 八个环节

|#|环节|职责|输入|输出|ARS 落点|谁做|
|-|-|-|-|-|-|-|
|S0|设计期|规则可编译、字段可定位、判定确定性|Skill 规则文本|规则 IR + locator 规范 + 失败分类|**L、C**（可事前算）|**我们**|

### 2.1 环节之间的六个契约（C1–C6，沿用）

|契约|交接|不变量|
|-|-|-|
|C1|S2 → 事件流|每条事件必有 seq / ts / tokens|
|C2|事件流 → S3|每条 claim 必有 locator，否则标 `NO\_LOCATOR`|
|C3|S0 → S1|每条规则必有编译状态（成功/失败码）|
|C4|S6 → 执行|任何"不验"必带 reason\_code|
|C5|S4 → 账本|每条检查必有 status + digest + 耗时|
|C6|账本 → 面板|只读，不得触发重算|

## 3\. ARS 在链路里的三个落点

同一个分数，三段合成，各有各的输入：

|落点|何时算|用到哪些环节的数据|能不能在跑之前得到|
|-|-|-|-|
|**落点 1：设计态分**|S0–S1 之后|L（locator 覆盖率）、C（编译通过率）|**能**——这是全链路唯一能事前算的指标|
|**落点 2：运行态分**|S2–S4 之后|D（确定性率）、F（新鲜度）、R（可复算率）|不能，需跑一次|
|**落点 3：治理态分**|S6–S7|扣分项 → 改造 → 重测|不能，需一轮改造|

`ARS = 0.25L + 0.25C + 0.20R + 0.15D + 0.15F`

**设计态分把 ARS 从"事后报告"变成"事前准入"**——这是它区别于所有既有工作的关键，也是 S6 闸门能成立的前提。

## 4\. 三条回路怎么闭合

### Loop A：验证回路（已实现）

```
规则 → 检查 → 证据 → 判定 → 回执
```

七篇工作分别占其中一段（LEDGER 证据图、ClaimReceipt 回执、SSEG 判定、VeriHarness 检查、2610.01348 四态、AFT 记录、AAT 格式）。**我们在这条回路里只做"引用与集成"，不做新算法。**

### Loop B：就绪度回路（未实现）

```
运行数据 + 判定结果
      ↓（五维打分）
    ARS 46（D 档）
      ↓（扣分项）
L 缺 12 个 locator｜C 有 3 条主观规则｜R 有 5 条缺字段
      ↓（改造方案，按 CU 排序）
补定位 → 拆规则 → 加字段 → 补 fixture
      ↓（重测）
    ARS 78（B 档）
      ↓（语料）
失败分类法 + fixture 库 + 基线
```

**这条回路是唯一会变厚的资产**：每接一个 Skill，语料多一批；每做一轮改造，分类法更准。Loop A 再强也不会因为多用一次而变好，Loop B 会。

### Loop C：经济回路（让 B 可执行）

```
CU 定价 → 每个改造动作的价格 → 最省成本达到目标档 → 预算分配
```

没有 C，B 就只是一句"应该改进"；有了 C，B 变成"花 34 CU 从 46 到 78"。**会计层在这里的作用是"预算表"，不是产品。**

## 6\. 谁建、谁借、谁不碰（沿用到全链路）

|环节|建 / 借 / 不碰|说明|
|-|-|-|
|S0 设计|**建**|规则 IR + 编译失败分类（10 条规则的窄版）|

|S7 治理|**建**|改造方案 + 语料库|

## 9\. 全链路的三个闸门（演示时的三个"卡点"）

|闸门|位置|判定|演示效果|
|-|-|-|-|
|G-设计|S1 之后|C < 50% → 不许装配|"这 4 条规则编不出来，先改规则"|
|G-发布|S6|ARS < 70（B 档）→ 不许进生产|"现在 46 分，不许发；改造后 78 分，放行"|
|G-预算|S6|预算耗尽 → accept\_with\_grade|"剩下 3 条接受 B 级，记在账上"|

三个闸门对应三种人：设计闸对 Skill 作者、发布闸对技术负责人、预算闸对合规审核员。

## 11\. 一句话总括

**正向链（Loop A）证明"发生了什么"，反向链（Loop B）回答"还能不能被审"，经济链（Loop C）说明"改到能被审要花多少"。
主线是 B：因为只有它会随着使用变厚；A 是别人的战场，C 是 B 的预算表。**
