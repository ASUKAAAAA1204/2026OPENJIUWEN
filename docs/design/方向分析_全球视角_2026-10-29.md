## 二、全球正在爆发的三个汇聚趋势

### 趋势1：Agent输出必须带证据链 + 不确定性

| 来源 | 怎么说 |
|------|--------|
| REA（360K stars） | "每个结论带证据来源 + 列出它不知道的东西"——Lilith AI专门评论说"这是它最有价值的特性" |
| VeriHarness（Google） | "分歧暴露正确选项，共识隐藏错误"——不是投票选多数，而是用证据消解分歧 |
| Gartner 2027 | "2028年70%企业要持续验证Agent决策"——没有证据链的Agent输出 = 不可审计 = 企业不敢用 |
| AWS CloudWatch Omni | 上周刚发布Agent可观测性，核心卖点是"每个Agent决策都有证据链" |

**本质**: Agent从"能做事" → "做事要留痕+敢被查"。这是从实验到生产的质变门槛。

### 趋势2：自我进化的Agent Skills

| 来源 | 怎么说 |
|------|--------|
| Hermes Agent（256K stars） | "The agent that writes its own skills"——7周从0到100K star，因为没有其他框架在做"内置学习闭环" |

| CollabFlow（10-25 arXiv） | 多Agent协作可以递归改进自己的协作模式 |
| Anthropic AAIF捐赠 | 70+平台、100万技能、2.8亿安装——Skills生态开始形成网络效应 |

**本质**: Agent从"预定义工作流" → "边干活边沉淀工作流"。Skills是Agent时代的"函数库"，但Agent自己会写函数。

### 趋势3：Always-On Agent（持久化Agent）

| 来源 | 怎么说 |

## 三、全球Top方向评分

**评分维度（每项10分）**: 全球前沿热度 / openJiuwen生态适配 / 32天DEMO可行性 / 差异化程度 / 开源社区认可度

### 🥇 Top 1：Agent决策证据链 + 不确定性标记 Swarm Skill

**一句话**: 给任何openJiuwen Swarm多Agent输出加一层"REA式证据链"——每个结论带来源+证据路径+明确标出不知道的东西。

#### 五条不可替代的论证

**1. REA 360K stars证明这是全球最热的Agent工程方向**
- 三周从41→360K stars，GitHub上最火的项目
- 核心理念不是反编译，而是"每个结论带证据 + 列出不知道的东西"
- 你做的是把这个理念从逆向工程移植到openJiuwen的多Agent Swarm协作里

**2. VeriHarness（Google Cloud AI Research，10-1 arXiv）是学术背书**
- "分歧暴露正确选项，共识隐藏错误"——这是REA核心理念的学术版
- 用同一个模型做生成+验证，有disagreement resolver和consensus challenger
- 你可以说"我们的Skill实现了VeriHarness的理念，但适配了openJiuwen Swarm的多Agent场景"

**3. Gartner 2027趋势是商业背书**
- 10-26刚发布：2028年70% G2000企业要Agent决策验证，2026年仅13%
- 你的Skill正好踩在这个需求爆发的前夜
- "Agent输出不可审计 = 企业不敢用"——你解决的是这个核心痛点

**4. openJiuwen生态完美适配**
- JiuwenSwarm有"全链路可观测"——你在这个基础上叠**语义级证据链**（不是token/latency trace，而是"这个决策依据了什么、引用了哪份文档、用了哪条规则"）
- openJiuwen有"Swarm Skills"标准——你做的就是一个符合Agent Skills标准的Skill包
- 256个现有Skills没有一个做Agent验证的——最干净的空白地带

**5. 32天完全可行**

```
技术实现方案：
1. 在Swarm Flow里加Interceptor层
2. 每次Agent输出时，自动收集：
   - 用到的工具调用（API name, params, result hash）
   - 引用的原始材料（文件路径, hash, 页码/字段定位）
   - 用到的规则/Skill（rule_id, 版本）
   - 模型的不确定性信号（自评置信度）
3. 自动生成"不知道的东西"列表：
   - 哪些信息缺失
   - 哪些证据互相冲突
   - 哪些假设未验证
4. 按openJiuwen Swarm Skills标准封装
5. DEMO：拿现有热门Skill（如"A股持仓智囊团"），给它叠加你的验证Skill
   → 展示证据链展开 + 不确定性高亮 + 冲突消解
```

## 七、32天DEMO实现路径（Top 1）

```
Phase 1（7天）：搞清楚openJiuwen Swarm Flow的内部机制
├── 跑通一个现有热门Skill（如"A股持仓智囊团"）
├── 理解Agent Core的Interceptor/Plugin机制
├── 确认哪些位置可以插入"证据收集"逻辑
└── 产出：Swarm内部机制笔记 + Interceptor插入点确认

Phase 2（10天）：实现证据链Skill MVP
├── 定义证据链数据结构：
│   evidence = {
│     tool_calls: [{api_name, params, result_hash}],
│     references: [{source_path, file_hash, locator}],
│     rules: [{rule_id, version, match_result}],
│     uncertainties: [{confidence, missing_info, conflicts, unverified_assumptions}]
│   }
├── 实现Interceptor层——每次Agent输出时自动收集证据
├── 实现"不确定性自动标记"——检查缺失输入、冲突证据、未验证假设
├── 按openJiuwen Swarm Skills标准封装
└── 产出：可运行的Skill MVP + 规范文档

Phase 3（8天）：做DEMO演示场景
├── 拿"A股持仓智囊团"或"代码评审专业组"作为被测Skill
├── 给它叠加你的验证Skill
├── 准备3个演示case：
│   Case A：正常输出，证据链完整
│   Case B：Agent结论有冲突证据 → VeriHarness式分歧消解
│   Case C：关键数据缺失 → 不确定性高亮
├── 录3分钟DEMO视频脚本
└── 产出：3个可演示case + 视频脚本

Phase 4（7天）：包装和提交
├── 写PPT（官方模板）
├── 画架构图
├── 准备"为什么现在做"的全球趋势数据
└── 提交
```
