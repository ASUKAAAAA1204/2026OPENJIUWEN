## 〇、差异化创新：我们不做什么，以及我们做什么

先把话说死——**这是最重要的部分**。评委会问"你和HoneyHive有什么区别"，你必须秒答。

### 现有竞品做到的 vs 我们做到的

| 竞品 | 它做什么 | 它**不**做什么 | 我们和它的关系 |
|------|---------|---------------|--------------|
| **HoneyHive / Braintrust / AWS Omni** | 🔵 **技术级trace**：token数、延迟、工具调用span图、OpenTelemetry指标 | ❌ 不收集**语义级证据**（这个决策为什么这么做、依据了哪段文档、用了哪条规则）<br>❌ 不做**不确定性自动标记**<br>❌ 不做**跨Agent分歧消解** | 我们做的是**他们的上层**——他们给你看到"Agent做了什么动作"，我们给你看到"Agent为什么这么做、有什么没把握、证据在哪里" |
| **VeriHarness（Google 10-1）** | 🟣 **学术验证方法**：同一个模型做生成+验证；disagreement resolver处理分歧；consensus challenger挑战共识 | ❌ 只在**benchmark环境**测试（HumanEval, MMLU），没落到生产Agent框架<br>❌ 没做多Agent Swarm的**协作级验证**（只验证单个长程任务）<br>❌ 没封装成可复用Skill | 我们把它**工程化**——把VeriHarness的验证协议做成openJiuwen Swarm Skill，适配多Agent场景 |
| **REA（360K stars）** | 🟢 **垂直场景证据链**：逆向工程MCP，每个反编译结论附行号证据 | ❌ 只在**逆向工程场景**（二进制/APK/固件）<br>❌ 没有**不确定性自动生成**（是反编译引擎告诉你哪些是混淆区，不是Agent自己判断）<br>❌ 没有**跨Agent分歧消解** | REA是我们的**一个DEMO场景**——我们的验证Skill可以套在REA的逆向Swarm上，就像它可以套在任何openJiuwen Skill上 |
| **Agentic UQ（arXiv 2601）** | 🟡 **模型内部不确定性**：Dual-Process框架，UAM记忆传播+UAR反思触发 | ❌ 只做**模型内部的置信度**（模型自评confidence score）<br>❌ 不做**外部证据链**（这个置信度为什么低？缺什么证据？）<br>❌ 没有**跨Agent传播** | 我们做的是**证据级不确定性**——不是"我觉得不太确定"，而是"我不确定，因为缺失X证据、Y证据和Z证据冲突" |

### 三句话讲清我们的创新

1. **世界上第一个语义级Agent证据链——不是token/latency trace，而是"这个Agent的这个决策依据了哪段输入、调了哪个工具、用了哪条规则"**
2. **世界上第一个可量化分级的Agent不确定性——不是模型自评confidence，而是"缺失输入/冲突证据/未验证假设/规则未覆盖"四象限分类**
3. **世界上第一个把VeriHarness学术验证协议落地成openJiuwen Swarm Skill——disagreement resolver + consensus challenger 适配多Agent协作场景**

```python
# Interceptor接口设计（伪代码，实际按openJiuwen API写）
class EvidenceInterceptor:
    
    # ============ 位置1：Agent输入侧 ============
    def on_agent_input(self, agent_id, input, context):
        """Agent收到任务时触发"""
        evidence = {
            "agent_id": agent_id,
            "timestamp": now(),
            "input_snapshot": hash(input),        # 输入的哈希（可追溯）
            "input_summary": summarize(input),     # 输入摘要（可理解）
            "expected_output_type": infer_from_skill(agent_id),
        }
        self.store(evidence)

    # ============ 位置2：Agent过程侧 ============
    def on_tool_call(self, agent_id, tool_name, params, result):
        """Agent调用工具时触发"""
        evidence = {
            "agent_id": agent_id,
            "tool_name": tool_name,
            "params_snapshot": hash(params),
            "result_snapshot": hash(result),
            "result_summary": extract_key_facts(result),  # 不是存全量，是存关键事实
        }
        self.store(evidence)
    
    def on_rule_match(self, agent_id, rule_id, rule_version, match_result):
        """Agent匹配Skill中的规则时触发"""
        evidence = {
            "agent_id": agent_id,
            "rule_id": rule_id,
            "rule_version": rule_version,
            "match_result": match_result,  # pass / fail / partial
        }
        self.store(evidence)

    # ============ 位置3：Agent输出侧 ============
    def on_agent_output(self, agent_id, output, confidence_self_report):
        """Agent产出结论时触发"""
        evidence = {
            "agent_id": agent_id,
            "output": output,
            "confidence_self_report": confidence_self_report,  # 模型自评
            "evidence_chain": self.link_to_prior_evidence(agent_id),  # 串联前面的证据
        }
        self.store(evidence)
```

#### 模块3：不确定性四象限分类器（5-7天）

**目标**：自动检测四种不确定性，**不依赖模型自评confidence**

```python
class UncertaintyClassifier:
    """
    检测逻辑：不是问模型"你确定吗？"，而是查证据链的客观属性
    """
    
    def detect(self, evidence_chain, skill_rules, all_claims_in_swarm):
        uncertainties = {
            "missing_inputs":     self._detect_missing(evidence_chain, skill_rules),
            "conflicting_evidence": self._detect_conflicts(all_claims_in_swarm),
            "unverified_assumptions": self._detect_unverified(evidence_chain, skill_rules),
            "uncovered_by_rules":  self._detect_uncovered(evidence_chain, skill_rules),
        }
        uncertainties["derived_confidence"] = self._calculate_confidence(uncertainties, evidence_chain)
        return uncertainties

    # ============ 第一象限：缺失输入 ============
    def _detect_missing(self, evidence, rules):
        """
        检查：Skill的规则要求哪些输入？实际提供了哪些？
        差集 = 缺失输入
        """
        required_inputs = rules.get("required_input_fields", [])
        provided_inputs = evidence.get("references", [])
        missing = set(required_inputs) - set(provided_inputs)
        return [{"field": m, "severity": self._severity(m, rules)} for m in missing]

    # ============ 第二象限：冲突证据 ============
    def _detect_conflicts(self, all_claims):
        """
        检查：不同Agent对同一事实的陈述是否矛盾
        用自然语言匹配+数值对比
        """
        conflicts = []
        claims_by_topic = group_by_topic(all_claims)
        for topic, claims in claims_by_topic.items():
            # 数值对比：两个agent给出的数值差超过阈值
            numeric_claims = [c for c in claims if is_numeric(c["statement"])]
            if len(numeric_claims) >= 2:
                values = [extract_number(c["statement"]) for c in numeric_claims]
                if max(values) - min(values) > THRESHOLD:
                    conflicts.append({
                        "topic": topic,
                        "values": values,
                        "agents": [c["agent_id"] for c in numeric_claims],
                    })
            # 自然语言矛盾：用LLM做pairwise contradiction check（轻量，只在同topic的claim之间跑）
            linguistic_conflicts = llm_check_contradictions(claims)
            conflicts.extend(linguistic_conflicts)
        return conflicts

    # ============ 第三象限：未验证假设 ============
    def _detect_unverified(self, evidence, rules):
        """
        检查：Skill规则里有没有"假设"、"假定"、"默认"这类关键词？
        这些假设有没有被显式验证过？
        """
        unverified = []
        assumptions_in_rules = extract_assumptions(rules)  # 正则匹配"假设|假定|默认|前提"
        verified_assumptions = evidence.get("verified_assumptions", [])
        for a in assumptions_in_rules:
            if a not in verified_assumptions:
                unverified.append({
                    "assumption": a,
                    "rule_id": rules["rule_id"],
                    "severity": "low",  # 假设未验证通常不是致命的
                })
        return unverified

    # ============ 第四象限：规则未覆盖 ============
    def _detect_uncovered(self, evidence, rules):
        """
        检查：Agent实际用到的数据/场景，有没有完全没被Skill规则覆盖？
        """
        uncovered = []
        agent_actions = evidence.get("tool_calls", []) + evidence.get("references", [])
        covered_scenarios = rules.get("covered_scenarios", [])
        for action in agent_actions:
            scenario = classify(action)  # 这个action属于什么场景？
            if scenario not in covered_scenarios:
                uncovered.append({
                    "action": action,
                    "uncovered_scenario": scenario,
                    "severity": "medium",
                })
        return uncovered

    # ============ 核心：证据质量加权计算（不信任模型自评！）============
    def _calculate_confidence(self, uncertainties, evidence):
        completeness = 1.0 - (len(uncertainties["missing_inputs"]) / max_required_inputs)
        consistency = 1.0 - (0.3 * len(uncertainties["conflicting_evidence"]))  # 每发现一处冲突扣0.3
        rule_coverage = 1.0 - (len(uncertainties["uncovered_by_rules"]) / total_rule_scenarios)
        confidence = 0.4 * completeness + 0.3 * consistency + 0.3 * rule_coverage
        # 严重缺失输入额外扣分
        for m in uncertainties["missing_inputs"]:
            if m["severity"] == "high":
                confidence -= 0.15
        confidence = max(0.0, min(1.0, confidence))
        return {
            "overall": round(confidence, 2),
            "breakdown": {...},
            "method": "evidence_quality_weighted_average",
            "note": "derived from evidence properties, NOT model self-report",
        }
```

#### 模块4：VeriHarness式分歧消解器（5-7天）

**目标**：当两个Agent给出矛盾结论时，用**原始证据**消解，而不是投票

```python
class DisagreementResolver:
    """
    基于VeriHarness (arXiv 2610.00972) 协议，但适配openJiuwen多Agent Swarm场景
    
    VeriHarness的核心洞察：
    - 投票共识可能隐藏共享错误
    - 分歧暴露正确的替代方案
    - 用证据消解分歧，而不是取多数
    
    我们的适配：
    - VeriHarness在benchmark里跑同一个Agent N次取分歧
    - 我们在Swarm里天然有多个Agent（不同角色），直接用它们的分歧
    """
    
    def resolve(self, claim_a, claim_b, context):
        """
        claim_a, claim_b: 两个不同Agent对同一事实的矛盾陈述
        context: 原始输入材料 + 所有工具调用 + 所有规则
        """
        
        # Step 1: 提取矛盾点（精确到数值或关键词）
        contradiction = self._extract_contradiction_point(claim_a, claim_b)
        # 例: contradiction = {"topic": "PE_ratio", "values": [12.3, 11.8], "agents": ["analyzer", "auditor"]}
        
        # Step 2: 回到原始证据，看两个Agent各自用了什么数据源
        evidence_a = self._trace_back_to_raw_material(claim_a, context)
        evidence_b = self._trace_back_to_raw_material(claim_b, context)
        # 例: evidence_a = {source: "finance_api", date: "10-28"}
        #     evidence_b = {source: "同花顺导出", date: "10-27"}
        
        # Step 3: 按可验证的优先级排序证据质量
        ranked = self._rank_by_evidence_quality([evidence_a, evidence_b])
        # 排序标准：更新时间 → 数据源权威性 → 格式规范度
        
        # Step 4: 取最优证据的结论，同时标注消解依据
        best = ranked[0]
        resolution = {
            "original_claims": [claim_a, claim_b],
            "contradiction_point": contradiction,
            "resolution": best["claim"],
            "resolution_reason": f"以{best['evidence']['source']}（{best['evidence']['date']}）为准，因为{ranked[0]['rank_reason']}",
            "evidence_used": best["evidence"],
            "confidence_after_resolution": self._boost_confidence(best, context),
        }
        return resolution
    
    def _challenge_consensus(self, all_claims, context):
        """
        VeriHarness的consensus challenger部分：
        如果所有Agent都给出相同结论→主动攻击这个共识，找它可能错的方式
        
        我们的适配：
        - 不在benchmark里随机挑战
        - 只在有高价值风险的场景触发（比如结论影响最终判断）
        """
        consensus_claims = find_all_same_claims(all_claims)
        challenges = []
        for claim in consensus_claims:
            # 用LLM生成3种"这个共识可能错"的假设
            failure_modes = llm_generate(
                prompt=f"以下结论被所有Agent同意：{claim['statement']}。"
                       f"请提出3种可能让这个共识是错的方式。"
                       f"考虑：数据源版本错误、下游假设错误、规则本身有缺陷。"
            )
            for mode in failure_modes:
                # 用原始证据验证每种假设
                verification = self._test_failure_mode(mode, context)
                if verification["might_be_true"]:
                    challenges.append({
                        "claim": claim,
                        "failure_mode": mode,
                        "evidence_for_challenge": verification,
                        "severity": verification["risk_level"],
                    })
        return challenges
```

## 五、如何制作出真实的创新性（不是讲故事）

### 创新不是"我加了Interceptor"，而是以下三件事**同时成立**

#### 创新点1：证据链是**语义级**的，不是技术级的

```
❌ 现有方案（HoneyHive）:
   span: {name: "get_pe_ratio", latency: 230ms, tokens: 42}
   → 你能看到"调了get_pe_ratio"，但看不到"为什么调它、它的返回值支撑了哪个结论"

✅ 我们的方案:
   evidence: {
     tool: "get_pe_ratio",
     params: {symbol: "A", date: "10-28"},
     result: "12.3",
     role: "支撑'PE低于行业平均'结论的直接数据",
     linked_claim: "claim-uuid-xxx"
   }
   → 这个证据链是给**人**读的，不是给监控面板看的
```

#### 创新点2：不确定性是**证据驱动**的，不是模型自评的

```
❌ 现有方案（Agentic UQ）:
   confidence: 0.72  ← 这是模型自己说的"我觉得我72%确定"
   → 问题：模型可能过度自信（80%但其实错了）或过度保守

✅ 我们的方案:
   derived_confidence: {
     overall: 0.72,
     breakdown: {
       evidence_completeness: 0.85,      # 证据链覆盖率85%
       evidence_consistency: 0.60,        # 有证据冲突（两个Agent给了不同值）
       rule_coverage: 0.70,              # 规则覆盖70%
     },
     method: "evidence_quality_weighted_average",  # 明确不是模型自评！
     uncertainties: {
       missing: ["创业板PE数据缺失"],
       conflicts: ["finance_api 12.3 vs 同花顺 11.8"],
       uncovered: ["Skill没考虑市值权重"],
     }
   }
   → 这个置信度是**算出来的**，有明确的扣分原因
```

#### 创新点3：分歧消解是**原生适配openJiuwen Swarm的**，不是benchmark版的

```
❌ VeriHarness（学术版）:
   在benchmark里跑同一个Agent N次 → 收集分歧 → resolver消解
   → 问题：为什么要跑N次？生产里不会这么干

✅ 我们的方案:
   openJiuwen Swarm天然有多个不同角色的Agent
   → analyzer-agent给PE=12.3
   → auditor-agent给PE=11.8
   → 分歧天然存在，直接喂给disagreement resolver
   → resolver回到原始证据，按数据源更新时间/权威性排序
   → 输出"以finance_api 10-28数据为准，因为比同花顺10-27新"
   → 这是**生产级**的分歧消解，不是benchmark trick
```
