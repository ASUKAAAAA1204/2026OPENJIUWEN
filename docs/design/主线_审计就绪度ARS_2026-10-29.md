# 主线：审计就绪度（Audit Readiness）

> 日期：2026-10-29
> 目的：给项目一条**能当壁垒、能讲实用、能讲创新、能讲发展**的主线，其余模块全部降为它的支撑件。
> 一句话：**我们不验证结论，我们先度量"这件事能不能被验证"。**

---

## 1. 主线是什么

**定义**：审计就绪度（ARS）是一个 0–100 的**覆盖率指标**，度量"一个 Skill 的输出在多大程度上可被第三方独立复核"。

它不是一个功能，是一个**可度量、可提升、可交易的对象**：

- **可度量**：五个分项，全部可从证据包算出，不依赖人工主观打分；
- **可提升**：每个扣分项对应一组具体改造动作（补 locator、拆主观规则、加字段、加 fixture）；
- **可交易**：采购方问"你这个 Skill 能不能审"，卖方答"46 分，补 34 CU 能到 78 分"。

**它替换掉的旧中心**：证据链不再是产品，而是 ARS 的**计量单位**；调度不再是产品，而是**提升路径的成本排序**；债务不再是产品，而是**ARS 的扣分存量**。

一句话结构：

```
Rail 采集 → 证据包（计量单位）→ ARS 五维打分 → 扣分项 → 改造方案（最省 CU）→ 重测 → ARS 上升
                                      ↑                                      │
                                      └──────── 语料 / 分类法 / 基线 ─────────┘
```

---

## 2. 五个分项（评分口径公开）

| # | 分项 | 定义 | 权重 | 为什么是它 |
|---|---|---|---|---|
| L | **可定位率** | 有精确 locator 的 claim / 总 claim | 25 | 没有定位就没有复核，这是最硬的前提 |
| C | **可编译率** | 能编译成可执行检查、且通过 fixture 的规则 / 总规则 | 25 | 规则不可编译 = 结论永远无法被机器复核 |
| R | **可复算率** | 第三方仅凭证据包能重算出同一结论的 claim / 总 claim | 20 | 这是"可审计"的操作性定义 |
| D | **确定性率** | 非 LLM 判定的检查 / 总检查 | 15 | 用 LLM 判断 LLM，等于没审 |
| F | **新鲜度** | 输入 digest 未变化的 claim / 总 claim | 15 | 过期结论等于没结论 |

`ARS = 0.25L + 0.25C + 0.20R + 0.15D + 0.15F`（各项先归一化到 0–1）

**分档**：A ≥85｜B 70–84｜C 50–69｜D <50。
**只报整数与分档，不报小数**——这是防止"假精度"的第一条纪律。

### 为什么这五项而不是别的

每一项都必须满足两个条件：**能从证据包直接算出**、**有对应的改造动作**。
不满足的（比如"结论正确率"）一律不进评分——那是另一件事，且不可从证据推断。

## 3. 提升闭环（这是"发展性"的载体）

```
测（ARS 46，D 档）
  → 看扣分项（L 缺 12 个 locator；C 有 3 条主观规则；R 有 5 条缺字段）
  → 生成改造方案（按 CU 成本排序）
  → 执行（补定位 / 拆规则 / 加字段 / 补 fixture）
  → 重测（ARS 78，B 档）
  → 对照曲线（花了 34 CU，涨 32 分）
```

**这条闭环就是产品**：它把"审计"从一次性检查变成一条**可管理的增长曲线**。而且——每一轮改造都会留下语料（哪类规则编不出来、哪类字段总缺），下一轮更准。

---

## 4. 为什么它是壁垒（三个机制，逐条对）

| 机制 | 在本主线里怎么体现 | 抄走追平 |
|---|---|---|
| **累积正确性** | 编译语料 + 失败分类法：每接一个 Skill，多一批"这类规则编不出来"的样本，评分与建议更准 | 2–3 个月（要重攒语料） |
| **规模经济** | 全局事实缓存 + 增量重算：Skill 越多、调用越频繁，单位改造成本越低 | 2–3 个月 |
| **切换成本** | 一旦采购方用 ARS 做准入（"低于 B 档不上线"），换供应商就要换标准 | 需要平台采纳，先发者占位 |

而"会计层"（定价/调度/曲线）**不构成壁垒**——它一周能被复刻。所以它的定位是 ARS 的**成本核算器**，不是产品本体。这一点必须写清楚，否则答辩会被问穿。

---

## 5. 为什么它同时满足四个评分维度

| 维度 | 回答 |
|---|---|
| **创新性** | 过去 90 天的七项工作（LEDGER / ClaimReceipt / SSEG / VeriHarness / 2610.01348 / AFT / AAT）**全部在验证输出**，没有一项度量"输出能不能被验证"。这是唯一没被占的位置 |
| **实用性** | 它回答的是采购与合规的真实问题："这套 Agent 能不能过审"。而且给出的不是一个形容词，是一个分数加一份报价 |
| **技术可行性** | 五项全部可从证据包算出；最难的"可编译率"只需做窄版（10 条规则 + fixture），3–5 人日 |
| **场景价值** | 三个买家：平台方（上架质量门）、企业采购（准入尽调）、审计方（复核前置） |
| **用户体验** | 一个分数 + 五个扣分项 + 一条曲线。比任何 trace 面板都好懂 |
| **商业价值** | "把 ARS 从 46 提到 78 要 34 CU"——这是唯一能被 CFO 听懂的一句话 |

## 8. 评分必须可信（否则整个主线崩）

一个"分数"最容易被质疑的是"你凭什么给这个分"。三条防线：

1. **口径公开**：五项定义与权重写进报告，任何人都能重算。
2. **信度**：两名成员独立给 20 个 Skill 打分，报告一致率（目标 κ ≥ 0.7）。
3. **效度**：拿 20 条历史上有争议的结论，检验"低分是否对应'审计时被问倒'"（目标：低分档被问倒率显著更高）。

做不到这三条，ARS 就是玄学；做到，它就是标准。

---

## 9. 答辩三句

1. "别人在验证结论，我们在验证'这个结论能不能被验证'——而且给一个 0–100 的分。"
2. "这个 Skill 现在 46 分，补 12 个定位、拆 3 条主观规则，花 34 CU，能到 78 分。"
3. "分数会随每次改造上升，而这个上升曲线和背后的失败语料，是别人三个月内攒不出来的。"

---

## 10. 一句话总括

**项目的主线不是"证据链"，也不是"验证预算"，而是"审计就绪度"——**
**它把不可见的"能不能审"变成一个数字，把改造变成一条有价格的曲线，把每次改造变成谁也抄不走的语料。**
