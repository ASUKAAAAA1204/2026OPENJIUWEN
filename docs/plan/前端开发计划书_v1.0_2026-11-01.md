## 0. 一句话

质量不是靠最后一周测出来的，是靠**每次提交都被同一套命令拦一次**。本计划书的价值就是把"感觉没问题"换成"7 道门全绿"。

## 2. 工程规范

### 2.1 语言与类型

- TypeScript `strict: true`，禁止 `any`（确需时写 `unknown` + 窄化，PR 里说明）；
- 组件 props 一律 `defineProps<Props>()` 泛型写法，禁止运行时对象写法混用；
- 事件命名 `update:*` / `action:*`，禁止 `@click` 直接透传到业务逻辑；
- `api/types.ts` 是唯一契约源，**任何字段改动必须先改这里并通知后端守门人**。

### 2.2 代码风格

| 工具 | 规则 |
|---|---|
| ESLint | `eslint-plugin-vue` recommended + `typescript-eslint` strict |
| Prettier | 单引号、无分号、printWidth 100、`vueIndentScriptAndStyle: false` |
| Stylelint | 禁止在组件内写十六进制颜色；颜色只能引用 `var(--token)` |
| 命名 | 组件 PascalCase；composable `useXxx`；工具函数 camelCase；文件与导出同名 |

Stylelint 关键规则：

```json
{
  "rules": {
    "color-no-hex": true,
    "declaration-property-value-disallowed-list": {
      "/color/": ["/^#/"]
    }
  },
  "ignoreFiles": ["src/styles/tokens.css"]
}
```

### 2.3 目录与文件边界

- 组件不 import 其他组件的内部 state；数据 props 下行、事件上行；
- 业务状态只在 `useReport` / `useGate` 两个 composable 中；
- 不新增第三方运行时依赖，除非满足：MIT/Apache、gzip < 30KB、有维护、PR 中写明替代方案。

### 2.4 提交与分支

| 项 | 约定 |
|---|---|
| 分支 | `feat/<scope>`、`fix/<scope>`、`chore/<scope>`，scope 用组件或模块名 |
| 提交 | Conventional Commits：`feat(score-card): ...` |
| 粒度 | 一个提交只做一件事；组件 + 其测试同提交 |
| 合并 | 只允许 squash merge 到 `main`，历史保持线性 |
| 禁提交 | `dist/`、`.env`、截图临时文件、`node_modules` |

## 3. 测试策略

### 3.1 分层与责任

| 层 | 范围 | 工具 | 何时跑 |
|---|---|---|---|
| L0 静态 | 类型、lint、样式规范 | vue-tsc / ESLint / Stylelint | 每次提交（pre-commit + CI） |
| L1 契约 | 4 份 mock 与 `types.ts` 一致 | zod schema（`scripts/check-contract.ts`） | 每次提交 |
| L2 单元 | `useTween`、`flip`、`useGate`、`format`、`useReport` | Vitest | 每次提交 |
| L3 组件 | 12 个组件的 4 种状态渲染 | Vitest + @vue/test-utils | 每次 PR |
| L4 端到端 | 4 场景 × 主流程 + 分支 | Playwright | 每次 PR（缓存浏览器） |
| L5 视觉 | 6 张关键状态截图比对 | Playwright `toHaveScreenshot` | 合并到 main |
| L6 可访问性 | 3 个关键状态 | axe-core | 合并到 main |

### 3.2 组件测试的最小要求（每个组件 4 条）

1. 正常态渲染（含 props 断言）；
2. 缺失态（NA / MISSING / PARTIAL 至少各一条）；
3. 交互回调触发（emit 事件名与载荷）；
4. 键盘可达（Tab 聚焦 + Enter/Space 触发）。

### 3.3 E2E 必测清单

| # | 用例 | 断言 |
|---|---|---|
| E1 | `?mock=pre` 打开 | 47 / D / 五维计数与 mock 一致 |
| E2 | 点 L 维 | 抽屉打开、11 条未定位、≤2 层到详情 |
| E3 | 发起发布 | 弹窗出现、无 X、Esc 不关闭、焦点在主按钮 |
| E4 | 执行修复 | 切到 79 / B、曲线含 `(34,79)` |
| E5 | 豁免 | 未选原因码不可提交；提交后 banner 常驻 |
| E6 | `?mock=partial` | 总分 `—`、闸门按钮禁用 |
| E7 | `?mock=design` | 只显示 C、无阻断弹窗、design_ack 提示 |
| E8 | 导出 | 下载文件名与内容数字一致 |
| E9 | 键盘 | 仅用 Tab/Enter/Esc 完成 E1–E5 |
| E10 | reduced-motion | 无位移/缩放动画，数字直达 |

### 3.4 视觉回归截图集

1280×720，固定字体加载完成后截图：

1. `pre` 一屏；2. `pre` 抽屉打开；3. `pre` 阻断弹窗；4. `post` 一屏；5. `partial` 一屏；6. `design` 一屏。

## 4. 质量门（G0–G6）

| 门 | 时机 | 检查项 | 不通过后果 |
|---|---|---|---|
| **G0** | 本地提交前 | lint-staged（ESLint + Stylelint + Prettier）、`vue-tsc --noEmit`（增量） | 无法提交 |
| **G1** | 推送 PR | typecheck、lint、契约校验、单测、build、体积预算 | PR 标红，不可合并 |
| **G2** | PR 评审 | 自检清单（§5）+ **组件截图审查（§6.1）** + 契约变更需守门人 approve | 不合并 |
| **G3** | 合并 main | E2E 全量 + 视觉回归 + axe | main 标红，冻结发版 |
| **G4** | 每周五 | 四场景人工走查（鼠标/键盘/reduced-motion 各一遍） | 进入下周缺陷池，P1 当周修 |
| **G5** | 12-22 | 演示环境验收：构建产物静态托管、离线可用、备用机验证 | 不进入彩排 |
| **G6** | 12-25 彩排 | 2:40 分镜全流程 + 断网演练 + 备用录屏 | 只允许 P0 修复 |

### 4.1 对应命令

```bash
npm run lint        # ESLint + Stylelint
npm run typecheck   # vue-tsc --noEmit
npm run check:contract
npm run test        # Vitest + coverage
npm run test:e2e    # Playwright
npm run test:visual
npm run test:a11y
npm run budget      # vite build + gzip 体积核算
npm run shots       # 组件截图（供 §6.1 审查）
npm run verify      # 以上全跑，CI 与本地一致
```

`npm run verify` 必须是**唯一真相**：CI 不额外加步骤，本地与 CI 跑同一条命令。

## 5. PR 自检清单（贴进 PR 模板）

- [ ] 只改了自己板块的文件；未触碰 `api/types.ts`（或已获守门人 approve）
- [ ] props/emit 有类型；无 `any`
- [ ] 四种文档状态（COMPLETE / PARTIAL / DESIGN_ONLY / 缺失维）至少手动看过一遍
- [ ] 颜色只用 token；未新增十六进制色值
- [ ] 动效只用 transform/opacity；已测 reduced-motion
- [ ] 键盘可达；弹窗 focus trap；`aria-label` 对分数有完整语义
- [ ] 新增/修改组件附 4 条测试
- [ ] 附 4 态截图（正常 / NA / MISSING / 样本不足）+ 边界截图，且审查结论为 PASS（§6.1）
- [ ] `npm run verify` 本地全绿
- [ ] 变更行数 ≤300（超出请拆 PR）

## 6. Definition of Done（单个组件）

一个组件"做完"= 同时满足 8 条：

1. props 与事件有类型，无隐式 any；
2. 正常 / NA / MISSING / 样本不足 四态均有渲染分支；
3. 有对应的 4 条组件测试；
4. 键盘可操作，焦点样式可见；
5. `prefers-reduced-motion` 下无位移；
6. 颜色/间距全部来自 token；
7. 在 1280×720 下无溢出、无截断；
8. 视觉回归基线已生成并提交；
9. **截图审查通过（§6.1），结论为 PASS**。

### 6.1 组件截图审查（强制规则）

组件写完后**不允许直接合并**，必须先出截图、按三个维度审一遍、给出 PASS/WARN/FAIL 结论。截图是评审材料，不是交付物；用眼睛审，不靠想象。

#### 6.1.1 必交截图（共 7 张）

| # | 截图 | 目的 |
|---|---|---|
| 1 | 正常态（COMPLETE，真实演示数据） | 基准观感 |
| 2 | NA 态（分母 0） | 缺失是否可辨、是否被误画成 0 |
| 3 | MISSING 态（未采集） | 与 NA 是否可区分 |
| 4 | 样本不足（PARTIAL，n<10） | 总分是否被正确隐藏 |
| 5 | 边界数据（见 6.1.3） | 极端值、长文本、空列表 |
| 6 | hover + focus 态 | 交互反馈是否可见、焦点是否清楚 |
| 7 | 1024×768 最小视口 | 是否溢出、是否换行错位 |

命名与存放：`docs/reviews/ui/<组件名>/v<n>-<状态>.png`，同组件最多保留 2 个版本，旧版删除或覆盖，避免仓库膨胀。

#### 6.1.2 审查三维度（逐条打勾）

**A. 可用性（3 秒原则）**

- [ ] 3 秒内能说出"这是什么、当前什么状态、我该不该点"
- [ ] 可点击区域 ≥32px，hover/focus 有明确反馈
- [ ] 文案无歧义：不出现"确定/取消"，不出现"置信度/正确率"
- [ ] 数字可读：分数一眼可辨，计数 `9/20` 与标签不混在一起
- [ ] 点击后去向明确（打开抽屉 / 弹窗 / 切换场景）

**B. 边界**

- [ ] `den=0`（NA）、`num=0`、`num=den` 三种极值均正确
- [ ] `score=null`、`band=null` 时不出现 `NaN`、`null`、`undefined`
- [ ] 最长文案：中文 30 字、英文无空格长串各一条，不撑破、不重叠
- [ ] 列表 0 条 / 1 条 / 12 条 / 200 条（PlanTable 5 行 + 溢出处理）
- [ ] 数值极端：`0 CU`、`999 CU`、`+0.00 增益`、负增益
- [ ] 浏览器 200% 缩放不裁切、不出横向滚动
- [ ] 1024×768 下不换行错位

**C. 美观**

- [ ] 8px 网格对齐；同类元素基线对齐
- [ ] 1px hairline 不出现双线、不出现 2px 灰边
- [ ] 颜色全部来自 token，无临时十六进制
- [ ] 装饰层不压数据（透明度 ≤0.15、不遮文字）
- [ ] 同类组件间距一致（同一 `gap` token）
- [ ] 衬线只出现在允许的 3 处；彩色只在档位与阻断
- [ ] 留白不空、不挤：区块间距 32 或 48，不出现 20/36 这类非网格值

#### 6.1.3 边界数据夹具

审查用固定夹具（不手改，写进 `ui/src/mock/edge.json`）：

| 字段 | 值 |
|---|---|
| L | 20/20（满） |
| C | 0/10（全失败） |
| R | 0/0（NA） |
| D | MISSING（未采集） |
| F | 5/20 + 一条 30 字中文扣分文案 |
| score / band | `null` / `null` |
| plan | `total_cu=0`、`predicted=null` |
| 列表 | deductions 0 条；actions 1 条（含负增益） |

#### 6.1.4 结论与处置

| 结论 | 条件 | 处置 |
|---|---|---|
| PASS | 三维度全部打勾 | 可合并 |
| WARN | ≤2 项轻微偏差（间距 1–2px、文案可优化） | 可合并，登记 S3，当周修 |
| FAIL | 任一可用性/边界项不通过，或美观项 ≥3 项不通过 | 禁止合并，修后重拍 |

审查人：组件作者自审 + 至少 1 名后端成员抽查（每周集中一次，30 分钟批量看当周截图）。结论写在 PR 描述里，格式：`截图审查：PASS（3 张关键图已附）`。

#### 6.1.5 截图怎么出

```bash
npm run dev                       # 起本地服务
npm run shots -- --component=ScoreCard --mock=pre
# 输出 docs/reviews/ui/ScoreCard/ 下 7 张图（Playwright 自动截）
```

禁止用手机拍屏、禁止缩放后截图、禁止截图里带浏览器边框或调试面板。

## 7. 性能预算与测量

| 项 | 预算 | 测量 |
|---|---|---|
| 入口 JS（gzip） | ≤260KB | `vite build` + gzip 统计 |
| 入口 CSS（gzip） | ≤40KB | 同上 |
| 字体（woff2，子集化） | ≤600KB | `glyphhanger`/`pyftsubset` 产出后统计 |
| 首屏渲染（mock） | ≤1000ms | Performance 面板，冷启动 3 次取中位 |
| 场景切换可见变化 | ≤250ms | 录屏计时 |
| 单次长任务 | ≤100ms | Performance 面板 |
| 内存（30 分钟演示） | 无持续增长 | 任务管理器采样 3 次 |

字体必须**子集化**：仅保留界面用到的汉字 + 拉丁字母 + 数字，禁止整包 Noto Serif SC（整包 >5MB）。

## 8. 可访问性规范

| 项 | 要求 |
|---|---|
| 对比度 | 正文 ≥4.5:1；大号分数 ≥3:1；色块边界 ≥3:1 |
| 语义 | 分数元素 `aria-label="审计就绪度 47 分，D 档，低于发布门槛 70"` |
| 状态 | 阻断/通过/无数据必须有文字，不能只靠颜色 |
| 焦点 | 焦点环 2px `--blue`，不得移除 outline；弹窗 focus trap + 关闭后焦点回到触发元素 |
| 键盘 | Tab 顺序按视觉顺序；抽屉 Esc 关闭；弹窗 Esc 不关闭（按策划书） |
| 图表 | 曲线需有 `aria-describedby` 文本摘要（"从 47 分到 79 分，花费 34 CU"） |
| 表格 | 使用真实 `<table>`，表头 `scope="col"` |

## 9. 缺陷管理

### 9.1 分级与响应

| 级别 | 定义 | 响应 |
|---|---|---|
| S1 | 演示主线中断（打不开/阻断不出现/数字错） | 当天修，阻塞发版 |
| S2 | 分支流程错误（豁免失败、导出错、PARTIAL 出总分） | 24h 内修 |
| S3 | 视觉/文案偏差（颜色、间距、措辞） | 当周修 |
| S4 | 优化建议 | 进 backlog，不阻塞 |

### 9.2 流程

- 缺陷统一进 GitHub Issues，标签 `bug/S1..S4` + `ui`；
- 修复必须附带回归用例（E2E 或组件测试），否则不予合并；
- 12-20 起进入**代码冻结**：只允许 S1/S2 修复，任何视觉改动需负责人签字。

