# 成员 A M2 执行接线与集成计划

## 目标与边界

M1 的 SQLite、任务身份、意图/结果与四记录存储接口供执行端调用。M2 的 A 工作是持久化接线和故障验收；Gate、工具路径/命令/Git限制、真实框架拦截由 B 提供；账号、审批身份、权限与 HTTP 服务由 D 提供。A 不把本地零参数测试函数当成框架真实接入。

## 固定接口

1. B 在框架调用前提交当前 run/segment 的 IntentRecord，并提供规则快照、稳定 event_id、带时区 recorded_at。先调用 SnapshotStore.capture，再调用 DecisionJournal.record_intent；异常必须阻断调用并上报告警。
2. Gate=ALLOW 才可调用 execute_once；ASK 必须先由 D 认证身份，使用 RecordStore 追加参数摘要一致的 ApprovalRecord，再追加带 approval_id 的 ASK_ANSWERED；REWRITE 必须由 B 完成参数改写、受控入口检查与重新判定后提交 REWRITE_VALIDATED。
3. execute_once 接受 B 已限制工作目录与命令的闭包；A 不提供系统隔离。模型信息未知时明确保留 unknown，不编造版本。不能 JSON 编码/脱敏的结果不得伪称完成记录。
4. 恢复入口 recover_stopped_worker 仅接受已经确认退出的 worker 的决策名单；D/B 负责排他所有权与周期触发。60 秒阈值内不扫描成未知，达到阈值后追加且不重试副作用。
5. 每日签名使用 ledger.cli export，密钥在账本外，检查点外部保留。外部调度/密钥权限归部署端配置；命令存在不等于每日任务已安装。

## 执行顺序

- 核验 B 的三个正式框架 adapter 和受控执行入口、D 的认证与审批服务交付。
- 每个框架接入 A 持久化端口，运行 ALLOW/DENY/ASK/REWRITE、写失败、执行异常与重启恢复用例。
- 与 C 对齐新 JSONL/snapshot 包到 engine/v27 输入事实的显式映射；规则回放只能读取快照，不请求模型。未知事实保持未知。
- 将通过的集成用例纳入主回归，再推进 M3 的持久化事实/分析接口。

## 量化验收

- 3 框架分别全部场景通过，工具副作用计数与决策对应100%；拒绝/写入失败时调用次数0。
- ASK 身份伪造、参数替换、过期和重复批准均被拒绝；并发响应最多一次生效。
- 强制终止实际框架 worker 后：无自动重试，恢复事件在验收时间窗内产生；不能用纯函数测试替代。
- 意图及结果分别1000次持久写 P95≤5ms，FULL/WAL；保留失败首测，不只选择最快一轮。
- 独立复算读数与 C 手算夹具一致100%；哈希正确不得替代规则/事实复算。

## 当前真实依赖

仓库 adapters/__init__.py 与 gate/__init__.py 尚为基础结构；rail/jiuwen_adapter.py 是既有采集适配，不能据此认定三个正式受控 adapter 已交付。前端 API 草案也注明服务端尚未实现/确认。需要这些实际端口才能开展上述真实接线，接口文档和本地夹具不能替代。
