# 调整方案：目标与功能（v1.1）

> 日期：2026-10-30
> 触发：产品分析核对发现三项指标失真（D 恒满、F 口径错、R 近似占位）、度量自证、无 Studio 交付
> 原则：**只解决两件事——让分数有意义、让作品可提交。** 其余一律往后放。

---

## 1. 目标调整（四条，含放弃什么）

| # | 旧目标 | 新目标 | 放弃什么 |
|---|---|---|---|
| G1 | 五维全量打分，出一个 0–100 | **只报有真实方差的维度；不足时输出 partial，不给总分** | 放弃"每个 Skill 都能出一个整数"的完整性幻觉 |
| G2 | 我们算出分 | **分数必须能被独立复算，且不能由被测方自证** | 放弃"locator 声明即得分"的捷径 |
| G3 | 报告 + 曲线 + 闸门三件套 | **先做一条闭环：解析→判定→分数→拦截** | 放弃曲线交互、跨 Skill 对比、PDF 报告 |
| G4 | 功能完整 | **证据完整**：每个数字带 n、来源、口径版本 | 放弃"看起来专业"的复杂度 |

一句话：**从"算出一个分"改成"算出一个经得起问的分"。**

---

## 2. 功能调整（六组）

### A. 让 L 从"声明"变成"事实"

**问题**：`line_lookup()` 只看 claim 自己声明的 locator 是否"精确"，从不回源。
**改法**：新增 `LocatorResolver`
```
resolve(locator, source) -> RESOLVED | NOT_FOUND | VALUE_MISMATCH
```
- 打开源文件/数据，定位到 row/line/field；
- 比对声明值与实际值（数值容差、字符串规范化）；
- 只有 `RESOLVED` 才计入 L 的分子。

**验收**：构造 3 类样本（存在且一致 / 不存在 / 值不符），分类准确率 100%；L 项前后差值可解释。

### B. 让 R 从"有证据"变成"能重算"

**问题**：`recompute()` 是"有 evidence 就 VERIFIED"。
**改法**：最小可用的真重算
- 规则编译成表达式（`cmp`/`arith`/`agg`）；
- 从证据读入操作数 → 求值 → 与 claim 的数值比对；
- 表达式编译不出来 → `indeterminate`（不硬判）。

**验收**：10 条数值 claim，注入 3 个错误值全部被 refuted；无表达式时正确返回 indeterminate。

### C. 让 D、F 恢复方差

**D 的问题**：两个 checker 硬编码 `is_deterministic=True`，D 永远 1.0（虚高 15 分）。
**改法**：D = **通过 fixture 的确定性检查 / 总检查**；fixture 未过不计。去掉硬编码。

**F 的问题**：按证据条数算，PRD 要求按 claim 算。
**改法**：claim 级判定——该 claim 的全部证据 `fresh` 才算 fresh；任一条过期即 stale。

**验收**：同一数据集跑两次，D 与 F 都不再恒为 1.0；给出一组能产生 0.5–0.9 区间的样本。

### D. 让分数抗博弈（新增，原 PRD 缺失）

| 机制 | 做法 | 指标 |
|---|---|---|
| H1 held-out | 20 条 claim 不展示给 Skill 作者，只在评分时用 | held-out 与上报分差 ≤10 |
| H2 抽查 | 10% locator 人工回源核验 | 抽查一致率 ≥95% |
| H3 真实性比率 | `resolved_rate` 与 L 并列展示 | 两者差 ≤0.15 |
| H4 分/真实差 | 补 locator 后 L 涨、resolved 不涨 → 标 gaming | gaming 标记数 |
| H5 拆分检测 | 规则拆成等价琐碎谓词不计 C 增益 | 人工抽检 10 条 |

**验收**：构造一个"只补形式 locator"的 Skill，系统应给出 gaming 标记且 L 增益被折减。

### E. 让分数可被第三方验

- **独立 verifier**：另写约 200 行，不复用 checker 代码，只读 bundle，复算 10% 样本；
- **口径版本**：rubric v1.1 计算 hash 写进 ledger，分数可追溯到口径；
- **一致率**：独立 verifier 与主判定的差异 ≤5%。

**验收**：改一字节 → 链断；换口径 → 版本号变；独立复算可一键跑。

### F. 让作品可提交（硬要求）

| 项 | 现状 | 目标 |
|---|---|---|
| Studio 一屏 | 无（`ui/` 只有 package.json） | 分数 + 五维条 + 三条扣分 + 报价 + 拦截按钮 |
| CLI | 无 | `ledger run / score / verify / plan` |
| 测试 | 无文件 | ≥30 个用例，覆盖 resolver / recompute / D / F / 契约 / 链 |
| 一键复现 | 无 | `make demo` 跑完 200 claim 并出图 |
| 依赖声明 | 无 | THIRD_PARTY_NOTICES + SBOM |

**验收**：新机器 `make demo` 一次成功；Studio 里 3 次点击到证据；测试全绿。

### G. 口径修正（v1.1 定义）

| 维 | 旧 | 新 |
|---|---|---|
| L | 声明精确的 locator / 总 claim | **回源解析成功**的 locator / 总 claim |
| C | 可编译规则 / 总规则 | 编译通过**且 fixture 三条全绿** / 总规则 |
| R | 有证据即 verified | **独立重算一致**的 claim / 总 claim |
| D | is_deterministic=True / 总检查 | **fixture 通过的确定性检查** / 总检查 |
| F | fresh 证据条数 / 总证据条数 | **全部证据 fresh 的 claim** / 总 claim |

**Partial 规则**：任一维 N/A 或样本 <10 → 只报该维度与小计，**不报总分与分档**，并标 `PARTIAL`。

## 5. 验收清单（10 条，全部可现场演示）

1. L 由"回源解析"决定，三类样本分类 100%；
2. R 由"重算一致"决定，注入 3 个错误全部 refuted；
3. D 不再恒为 1，能展示 0.5–0.9 的区间；
4. F 按 claim 级计算，与证据条数解耦；
5. 样本 <10 时输出 PARTIAL，不给总分；
6. 只补形式 locator 的 Skill 被标记 gaming；
7. 独立 verifier 与主判定差异 ≤5%；
8. Studio 里 3 次点击到证据，闸门可拦截；
9. 新机器 `make demo` 一次成功，测试 ≥30 全绿；
10. 口径 hash 与版本号写在账本里。

## 7. 一句话

**这次调整不是加功能，是把"能算"改成"能证"：L 要回源、R 要真算、D/F 要有方差、分数要能被别人复算，然后把这一切装进 Studio 的一屏。**
