# TemisGuard v2.7 完整开发方案

版本：v1.0；日期：2026-11-18；状态：需求澄清完成后的实施基准。

## 1 依据与已确认决策

需求以 docs/prd/PRD-v2.7.md 为准。2026-11-15 两份方案作为历史技术输入；冲突时以本方案记录的用户决定及 PRD 行为验收要求为准。本方案不改写 PRD。

用户已确认：完整实现 v2.7，分阶段交付；四人开发，不以旧日历日期约束；本机部署；可以提供真实模型 API；实际支持 openJiuwen、LangGraph、OpenAI Agents SDK；主场景为代码助手的文件、命令、Git 发布和人工审批；限定工作目录与受控命令入口；本地账号登录与 Web 审批；本地仓库和模拟远端自动验收，加受控测试远端真实发布验证。

存储采用 SQLite 主账本，JSONL 为证据导出与独立校验格式。意图必须持久化成功后才能执行工具。实现服务端认证与 PRD 角色权限，不扩展多租户及企业单点登录。

## 2 当前证据与边界

本轮静态检查确认：根目录和 2026OPENJIUWEN-main 两套 Python 工程并存；根 pyproject 缺 rfc8785，嵌套版本声明 rfc8785==0.1.4；根 ui 是实际 Vue 工程；嵌套 jiuwen_adapter 的说明仍为 SDK 0.1.18，主要采集完成与异常事件，不能据此认定具备执行前阻断能力。

工作区已有大量修改、删除和未跟踪内容，全部视为既有工作，迁移前记录清单并逐文件比较，不覆盖、删除或自动提交。历史周报的测试数量、通过率及复用比例未在本轮复测，不能作为当前完成证明。

三框架版本兼容性和钩子语义尚未验证。本轮在线官方资料检索工具返回 404；以下接入均为待 spike 验证的设计，不声称已确认 SDK 接口可用。

## 3 交付范围与架构

覆盖 F1—F10、C1—C13、A1—A8 和 PRD 10.2 八项评测。旧 ARS 百分制及分档归档，不继续作为产品主口径。

结构：框架适配器 → 统一执行入口 guarded_call → 脱敏/白名单/策略/Gate → SQLite 事件账本 → 标记/债务/读数/回放 → 认证 API → Vue UI。

三适配器共用领域契约和门控服务，不复制规则引擎。OTel 仅用于观测，关闭后全部关键能力仍成立。Gate 不联网、不调用模型；读数与标记从已留存事实和策略快照计算，模型自评不进入标记。

建议包：contracts、adapters、policy、gate、ledger、marks、readings、runs、replay、auth、api；旧实现按差异分析选择复用，避免仅因文件名一致直接替换。

## 4 契约收敛规则

11 类决策维持白名单枚举，但生命周期与委派按 v2.7 修正：子任务独立 run，parent_run_id 关联；resume 保持 run_id 并递增 segment；深度超过 3 拒绝。无自身决策的纯编排运行不进入有效样本。

决策、证据、审批、债务分别建模。领域字段与 PRD 对齐；JSON 的 class 映射到 Python 安全别名，序列化仍输出 class。PRD Markdown 中多余转义符不是字段名的一部分。

Gate 四值、执行策略二值、事件类型、决策派生状态分别定义。事件不可修改，status 是事件投影，不能通过 UPDATE 改写历史。策略干预、人工应答及收尾事件关联原决策，利用 correlation_id 和 parent_decision_id 防止递归触发及重复计数；在契约测试中明确每类事件是否构成独立决策。

债务按 (run_id, decision_id, mark_type, origin_mark_id) 幂等识别，避免传播副本和事件重试重复计债。同一决策不同类标记分别计条；源等级决定债务权重，展示衰减不得降低原始债务。父子汇总展示分离，聚合按真实决策与债务身份去重。

M1 输出逐字段契约表、分母表、事件到状态转换表及手算样例后冻结；这些细节由实现与测试共同评审，不擅改 PRD 指标。

## 5 SQLite 账本与恢复

SQLite 运行在本机应用进程，启用外键、WAL 和可靠同步配置，使用短事务和单写者队列串行分配 seq、prev_hash、content_hash。禁止先执行工具再等待意图落账。

表建议：append-only ledger_events；内容寻址 snapshots；可重建的 runs/decisions/approvals/debts 投影；独立 users/sessions/roles；签名 checkpoints。投影可更新，证据事件不可更新或删除，使用数据库触发器和应用访问边界限制修改。

事件哈希沿用经验证的规范化算法，RFC8785 字节级定义、哈希覆盖字段与排除字段必须冻结。策略、白名单、依赖图及必要证据快照一起导出；只有摘要不足以独立复算的对象必须保留脱敏快照。输入执行实参留在内存，账本只保存脱敏版本；审批另外绑定受保护的参数指纹，不能用有碰撞的脱敏文本验证批准对象。

一次调用：准备脱敏快照 → 分类与规则判定 → 提交意图 → 审批/改写复判 → 验证批准参数 → 调用受控工具 → 追加结果。拒绝、超时、取消和异常也必须形成终态事实。意图写入失败则不执行；结果写入失败则重试、告警并保留待复核意图，不能谎称动作未发生。

恢复采用启动扫描和周期扫描。以 PRD 验收更严格的 60 秒内标记为准，记录恢复检测时延；业务超时与恢复阈值分别配置。UNKNOWN_OUTCOME 不能自动重试副作用，转人工复核。

哈希链检测中间篡改；每日及导出时生成记录长度与链头签名检查点，并保存数据库之外的验证副本。说明信任边界：同一主机管理员同时控制账本与密钥时，不能宣称抵御管理员伪造。JSONL 独立校验器不导入主写入实现。

性能验收分别测意图持久化及结果持久化 P95 ≤5ms，Gate 纯规则 P95 <50ms，记录本机硬件与并发。可靠性优先，未达指标要优化或明确差距，不通过关闭持久化伪造达标。

## 6 Gate、审批与执行边界

缺规则 DENY；高危故障阻断或按明确策略转人工，低危降级放行留痕；ASK 默认 30 秒，超时按风险类配置；REWRITE 最多重判两轮，仍未通过 DENY。degrade 仅在有真实只读能力的工具中生效。

审批通过服务端状态机原子消费：关联 decision_id、执行尝试、批准参数指纹、审批人和有效期；重复、过期、参数被替换均不得执行。审批身份来自登录会话，客户端不得指定 approver_id 冒充他人。ASK 等待不占用数据库写事务；重启后不自动批准。

工作根路径显式配置，解析真实绝对路径并校验边界；覆盖路径穿越、符号链接、Windows junction、大小写和 UNC。文件/Git 工具只操作允许根；命令使用结构化 argv 与允许清单，不能可靠解释的复合命令转 ASK 或 DENY。禁止把任意 shell 字符串放行当作受控入口。

此方案不提供操作系统级隔离。独立进程或未注册工具绕过入口属于覆盖边界；必须实测记录识别能力，不宣称能发现主机一切写入。已声明副作用但未分类按 PRD 记录 UNHOOKED；已进入解析但风险不可判定的命令转 ASK，两者区别进入用例。

## 7 三框架接入

openJiuwen 按 PRD 锁定 0.1.20.post1。LangGraph 和 OpenAI Agents SDK 在 M0 通过官方文档、安装环境和真实 spike 选择精确版本并锁定；有依赖冲突则使用各自虚拟环境，通过本机受控协议共用账本服务。

每框架必须证明：真实工具调用；DENY 时工具副作用计数为零；REWRITE 执行最终批准参数；ASK 批准/拒绝/超时；正常和异常结果各追加一次；恢复保持任务身份；并发上下文不串线；父子委派关联正确。

优先使用框架提供的工具包装或执行节点接入 guarded_call。只记录日志的回调不得充当阻断证据。LangGraph 的中断恢复与自身持久化仅映射业务 task/segment，不另造 run；OpenAI Agents SDK 的工具调用、handoff、取消路径逐一验证，不假设工具防护覆盖所有内置工具。

通用核心离线确定性测试、三框架真实运行测试、模型在线冒烟分层。stub 结果不算真实 SDK 和真实模型接入通过。模型密钥只在本地配置，禁止进入日志、账本与导出。

## 8 分析、管理与界面

八项读数严格采用 PRD 6.9 分子分母；零分母 N/A，债务是值与条目数；缺证据保留在复现率分母。Skill 最近 20 次有效运行等权聚合，至少 5 次且覆盖至少 3 类，展示样本量，不做综合评分或等级。

回放固化策略版本与快照，只重算确定性规则，不重新执行外部副作用。复现率与回放一致率分别实现与展示。策略版本不一致明确解释，不能悄悄切换当前规则。

发布闸与执行门分离，支持按角色启用、读数阈值及样本不足处理。整改报价以债务消解动作与成本依据报价，用三例人工基线验证误差 ≤20%；版本比较同时展示样本、策略版本和读数差，可比性不足必须提示。

Web 页面：登录、运行列表/段号/委派树、决策与证据详情、审批队列、标记传播、债务清单与消解、八项读数、规则回放、发布闸、版本对比、策略版本只读视图。mock 和 api 模式明确标识；mock 不作为最终验收。

## 9 API 与权限

本机默认绑定 127.0.0.1，优先同源部署。FastAPI 服务端实现本地账号、加盐密码散列、服务端会话、安全 Cookie、登录限流、会话失效和写接口 CSRF 防护；禁用公共默认密码。

查询接口：runs、decisions、evidence、readings、debts、replay-results、compare、policies。命令接口：审批应答、债务消解、发起回放、发布闸配置、导出。命令通过领域服务追加审计事件；GET 不触发重算和写账本。原方案只读 API 无法实现真实审批，因此由本方案明确扩展。

权限按 PRD 五角色矩阵逐接口与逐对象验证；开发者仅本人运行，运营仅所属 Skill，审计只读，导出留痕。审批授权需在权限表补明确可审批角色，建议管理员与获授权值班人员；实现前在契约评审确认，默认拒绝未授权审批。角色与 owner/Skill 由服务端建立，禁止信任前端过滤。

## 10 四人职责与集成方式

|成员|主责|交付|
|---|---|---|
|A|契约、SQLite、恢复、独立校验|事件模型、持久化、检查点、导出|
|B|策略、Gate、受控工具、三框架适配|执行前控制、真实接入、覆盖证据|
|C|标记、债务、读数、回放、管理计算|确定性分析与八项评测脚本|
|D|认证授权、API、Vue、端到端|真实审批、权限、可用界面|

这是职责建议，不要求四个智能体并行。四人共用契约与夹具；A/B 共同审执行前持久化，B/D 共同审审批参数绑定，A/C 共同审独立复算。每阶段先冻结接口再并行，每次集成跑受影响契约及回归。

## 12 验收证据

逐项维护 F/C/A 映射表，记录测试文件、命令、输入哈希、环境、输出路径与结论。

硬门禁包括：11 类记录覆盖100%；UNHOOKED 显式记录；三框架真实阻断；OTel 删除后100%独立复算；3轮对话+2次 resume 身份正确；崩溃后60秒内 UNKNOWN_OUTCOME；至少100次真实受控运行 shadow 人工标注误报≤5%；规则回放≥90%；10个红队样本至少8个阻断或转人工；三类标记各2条且3条消解的债务结果逐项正确。

shadow 统计预先冻结样本构成、阻断建议和人工真值定义，保留混淆计数；不以100次相同空跑充数。拦截开关在达到条件前不可正式开启，测试环境可显式测试阻断路径。

持久化/性能/权限/审批重放/路径穿越/并发/重启/异常都需负例。前端跑类型检查、构建、单测及真实 API 端到端，视觉与可访问性按已有项目门禁执行。最终本地 Git 测试与测试远端发布分开记录，实际远端地址由联调时配置。

## 13 实施起点与风险处理

下一步为 M0：先生成文件差异与环境基线报告，不立即删除根 src 或批量搬运未跟踪目录；真实测试后决定复用清单。框架 API 不符则调整适配器，禁止降低统一执行入口保证；SQLite 写延迟不达标先分析事务和磁盘；依赖冲突隔离环境；不可判定命令转人工；无法证明的覆盖范围如实标记。

剩余事项都是实施验证或低层设计评审：三框架锁定版本、审批授权补充表、事件分母细表、运行状态与 ASK 挂起转换、SQLite 性能和模型提供商配置。上述工作纳入阶段退出条件，不当成已经实现，也不再要求用户重复确认已确定范围。
