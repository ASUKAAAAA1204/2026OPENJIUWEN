# v2.7 本机会话前端契约草案

状态（2026-11-26 更新）：后端已实现匿名会话、登录、退出与 CSRF；平台测试覆盖 Cookie、Origin、限流与角色。前端通过 `?settings=api` 或配置来源选择器接入，合成数据不替代联调。

`GET /api/v27/session` 返回 `{ authenticated, csrf_token, identity }`。匿名会话也需服务端下发CSRF令牌；identity在匿名时必须null，在已认证时包含user_id/display_name/role/scope。角色为PRD五种角色之一。GET使用同源凭据、no-store；服务端响应也应Cache-Control: no-store。

`POST /api/v27/session/login`：JSON `{username,password}`；`POST /api/v27/session/logout`：空JSON对象。均带同源凭据与X-CSRF-Token，返回操作完成后的完整SessionSnapshot。服务端负责CSRF、Origin校验、账号验证、限流、会话轮换/撤销、HttpOnly/SameSite Cookie；浏览器不保存会话token或密码到localStorage/sessionStorage，不以客户端角色赋权。退出响应必须在服务端会话确已撤销后返回authenticated=false。

前端密码在提交时立即从表单清除；响应不匹配、401/403/404/429/服务错误或12秒超时后停止重复提交，要求重新读取确认，不自动重放。响应未知不宣称登录/退出成功。成功后重新加载整个工作区，丢弃内存中旧账号数据；新页面每次读取仍由服务端授权。页面卸载取消请求；取消网络请求不能撤销服务端已完成的会话操作。

第十六轮已统一审批应答、债务消解、管理配置/发布评估/整改报价、账本导出与回放的提交前会话检查：每次写入前重新 GET 会话，不缓存令牌；未认证或会话响应无效时不发出业务 POST。会话有效后，业务 POST 同时携带 X-CSRF-Token 和原有 Idempotency-Key，使用同源凭据与 no-store。提交后出现权限、冲突或未知结果仍要求刷新核对，不自动重放；审批/债务/管理在前置会话失败后也要求刷新表单。

本轮未接通真实认证服务，不宣称完成账号隔离、Cookie 属性、服务端 CSRF/Origin 校验或会话撤销联调。客户端会话预检查不能替代每个服务端写入接口的认证、角色/范围授权和 CSRF 验证。前置检查与提交之间发生会话轮换时，服务端须拒绝旧令牌，由用户重新核对后操作。

验收包括：会话与身份绑定、CSRF请求头、失败后刷新、防重复、登录/退出后页面重新加载、密码不在存储、四档截图与严重/关键axe检查。真实Cookie属性、限流、认证审计及跨账号数据隔离仍需服务端和端到端联调证据。

第二十轮增加全局会话指示器：进入工作区即读取会话，顶部区分确认中、已认证、未登录与无法确认；错误原因和可见范围通过可访问描述提供。用户可手动刷新，确认账号、角色或范围变化后重新加载整个工作区。顶部身份仅是最近一次读取结果，不能替代实时服务端授权；刷新失败时清除顶部旧身份，不冒充已登录。
