# v2.7 授权导出前端契约草案

状态（2026-11-26 更新）：后端已实现 `POST /api/v27/runs/{id}/export`，包含 SHA-256、审计标识与独立复核测试。合成 JSONL 不替代真实授权隔离验收。

`POST /api/v27/runs/{id}/export`，同源会话Cookie、X-CSRF-Token及Idempotency-Key；JSON请求 `{request_id,format:'jsonl'}`。发起前GET会话核验已认证状态。服务端按账号角色与运行归属核验导出权限，脱敏后登记审计，再返回文件；不能接受客户端身份声明作为授权。

成功响应Content-Type为application/x-ndjson，附以下头：

- X-Run-Id：必须与所请求运行完全一致。
- X-Export-Audit-Id：服务端已经登记的导出审计标识。
- X-Content-SHA256：响应原始字节的小写SHA-256。

JSONL每个非空行必须是含匹配run_id的对象。真实文件必须由服务端按正式导出schema包含独立复算所需决策、意图/结果事件、规则快照、证据及链字段。前端只核对传输指纹、JSONL可解析性与运行绑定，不把这些检查称为账本链或自包含性验证。

浏览器核对字节SHA-256后创建Blob下载，文件名由运行ID安全转换生成，不采用服务端任意文件路径。反馈为“已发起下载”，最终保存状态以浏览器下载列表为准。指纹/类型/运行/审计头缺失、无效UTF-8、空文件或跨运行记录均阻止下载。

401会话失效，403无导出权限，404接口未提供；网络失败和12秒超时显式提示。超时可能已经产生审计，不自动重试。再次操作需用户重新勾选确认。卸载或切换运行取消旧请求，旧响应不下载到新运行。大文件后续需服务端流式与独立摘要协议；当前实现读取完整响应，尚未实测超大文件的内存与性能边界。

本轮浏览器验收验证错误指纹无下载事件、正常文件名及实际下载字节、CSRF/幂等头、审计标识与四档布局；不包含真实服务端审计、脱敏、哈希链或跨账号权限隔离证明。
