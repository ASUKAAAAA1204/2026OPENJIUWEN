# PRD（子）：审计就绪度 ARS

| 项 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-10-29 |
| 归属 | 主 PRD v2.0 的**主线** |
| 一句话 | 把"这个 Skill 能不能被审"变成一个 0–100 的分，再把提升它的路算成价格 |
| 交付窗口 | 32 天（11-25 → 12-27），本线 15 人日 |

---

## 0. 定位

ARS 不验证结论，它度量**结论能不能被验证**。

在四性模型里，可观测/可追溯/可问责都已有归属，**可验证是空位**。ARS 补的就是这一格：

> 前三性证明"发生过什么"，第四性证明"结论站不站得住"。

时序上它横跨两端：

- **设计期**（L 可定位率、C 可编译率）——写下第一条规则时就能算；
- **治理期**（改造与重测）——每次修改后重算；
- 中间三段（运行、证据、判定）是它的数据源，不是它的战场。

---

## 1. 问题

### 1.1 三个买家的同一句话

| 买家 | 他问的问题 | 现在得到的回答 |
|---|---|---|
| 平台运营 | 这个 Skill 能不能上架 | "跑分不错"（跑分不解释可审计性） |
| 企业采购 | 买回来能不能过审 | "有日志"（有日志 ≠ 能复核） |
| 技术负责人 | 上线前还要补什么 | 说不清，只能等出事 |

**共同点**：都在问"能不能审"，而现有工具都在答"跑了什么"。

### 1.2 为什么现有工作不解决

七项工作（LEDGER / ClaimReceipt / SSEG / VeriHarness / 2610.01348 / AFT / AAT）全部度量**单次输出的质量**。ARS 度量的是**跨 Skill、跨时间的可验证性属性**，且它必须能在跑之前给出——这是它们结构上做不到的。

---

## 2. 目标与非目标

| # | 目标 | 判据 |
|---|---|---|
| A1 | 可复算 | 第三方拿数据能算出完全相同的分 |
| A2 | 可解释 | 每个扣分项有数字 + 一句人话 + 对应动作 |
| A3 | 可提升 | 执行方案后实际增幅 ≥ 预测的 70% |
| A4 | 可拦截 | 低于阈值时能在发布流程里卡住 |
| A5 | 会复利 | 语料随使用增长，且能展示增量 |

**非目标**：不预测正确率、不做单条结论的对错裁决、不做跨组织认证、不承诺"通过某标准"。

---

## 3. 使用场景

### S1 上架前（平台运营）

跑一次 → 得到 ARS 与五维分解 → 决定是否上架 / 退回改造。

### S2 采购前（企业）

对候选 3 个同类 Skill 各算一次 → 对比五维 → 用"到 B 档要多少 CU"做决策，而不是只看跑分。

### S3 发布前（技术负责人）

把发布闸接进流水线：ARS < 70 阻断；允许带豁免发布，但豁免需记 `accept_with_grade`。

---

## 4. 评分模型

### 4.1 五个分项

| 代号 | 名称 | 定义 | 权重 |
|---|---|---|---|
| L | 可定位率 | 有精确 locator 的 claim / 总 claim | 25 |
| C | 可编译率 | 通过编译且通过 fixture 的规则 / 总规则 | 25 |
| R | 可复算率 | 第三方仅凭证据包能重算出同一结论的 claim / 总 claim | 20 |
| D | 确定性率 | 非 LLM 判定的检查 / 总检查 | 15 |
| F | 新鲜度 | 输入 digest 未变化的 claim / 总 claim | 15 |

```
ARS = 100 × (0.25L + 0.25C + 0.20R + 0.15D + 0.15F)
```

### 4.2 归一化与边界

| 情况 | 处理 |
|---|---|
| 分母为 0（如没有规则） | 该项记 `N/A`，权重按剩余项重分配，并在报告注明 |
| 分母 < 10 | 标注"样本不足"，分档只作参考 |
| 证据包缺失 | 该 claim 计入 R 的分子分母都为 0（不算通过） |
| 过期但已重验 | 以重验后的 digest 为准 |

### 4.3 分档

| 档 | 区间 | 含义 |
|---|---|---|
| A | ≥ 85 | 可直接发布 |
| B | 70–84 | 可发布，需记录遗留债务 |
| C | 50–69 | 需改造后发布 |
| D | < 50 | 不允许发布 |

**只报整数与分档，不报小数。** 小数会制造不存在的精度。

### 4.4 红线

- 不得称其为"置信度""正确率""可信度分数"；
- 不得由 LLM 直接打分（必须由五项计数算出）；
- 不得在样本不足时不标注。

---

## 5. 数据来源与可算性

| 维 | 数据来源 | 计算时机 | 缺失时 |
|---|---|---|---|
| L | 输出解析的 locator（S3） | 设计期即可抽样估算，运行后精确 | 视为不可定位 |
| C | 规则编译结果（S0/S1） | 设计期 | 视为不可编译 |
| R | 第三方复算演练（S4/S5） | 运行后 | 计入未通过 |
| D | 检查类型统计（S4） | 运行后 | 视为 LLM 判定 |
| F | digest 比对（S3） | 每次运行 | 视为过期 |

**关键**：L 与 C 在设计期就能算，这让 ARS 能当"准入"用；R/D/F 必须等运行，这让 ARS 能当"体检"用。

---

## 6. 功能需求

### 6.1 ARS-1 打分器

**输入**：证据包集合 + 规则编译结果 + 检查记录。
**输出**：`{score, band, dims:{L,C,R,D,F}, n_claims, n_rules, warnings[]}`。
**规则**：严格按 §4.1；`N/A` 重分配；样本不足打 warning。

**验收**：第三方脚本复算，差异 = 0；`warnings` 覆盖所有边界情况。

### 6.2 ARS-2 扣分解释器

**输出**：每个分项一句人话 + 一个数字 + 一个动作指针。

示例：
> **可定位率 0.42**：12 条结论里 5 条有精确到行的定位，7 条只有文件名。
> → 补定位（约 0.7 CU/条）

**验收**：任一分项点开 ≤2 层可达具体条目列表。

### 6.3 ARS-3 改造方案器

**输入**：扣分项 + 动作库 + CU 单价。
**输出**：按"分/CU"降序的动作列表 + 目标档 + 总价 + 预期分。

```yaml
plan:
  current: 46
  target_band: B          # 用户指定，默认 B
  actions:
    - {act: add_locator, n: 7, cu: 4.9, gain: 11.7}
    - {act: split_rule,  n: 3, cu: 12.0, gain: 8.3}
    - {act: add_field,   n: 2, cu: 6.0, gain: 4.1}
  total_cu: 22.9
  predicted: 70.1
```

**算法**：贪心——每轮取 `gain/cu` 最高的动作，直到达到目标档或边际枯竭（<0.5 分/CU）。
**验收**：预测与实际重测偏差 ≤30%（A3 放宽到 70% 兑现率）。

### 6.4 ARS-4 重测与曲线

- 执行动作后自动重测，记录 `(cu, score)` 点；
- 画提升曲线（当前点 + 目标档线）；
- 支持"预算上限"模式：给定 CU，输出能达到的最高分。

**验收**：一条命令重跑出同一张图。

### 6.5 ARS-5 三道闸门

| 闸 | 位置 | 规则 | 输出 |
|---|---|---|---|
| 设计闸 | S1 之后 | C < 0.5 → 不许装配 | 阻断 + 失败分类 |
| 发布闸 | S6 | ARS < 70 → 阻断 | 阻断 + 方案报价 |
| 预算闸 | S6 | 预算耗尽 | `accept_with_grade` + 原因码 |

豁免：允许人工豁免，但必须落 `waiver` 记录（谁、何时、理由、有效期）。

**验收**：三个闸各有可演示的拦截场景；豁免可查。

### 6.6 ARS-6 编译失败分类法 + 语料

四类失败码：

| 码 | 含义 | 典型动作 |
|---|---|---|
| `NO_LOCATOR` | 规则引用的事实没有可定位字段 | 补 locator |
| `SUBJECTIVE_RULE` | 规则含"合理/适当/良好"等不可判词 | 拆成可判谓词 |
| `MISSING_FIELD` | 规则要求的输入不存在 | 补字段或降级规则 |
| `NON_DETERMINISTIC` | 判定依赖 LLM 或随机 | 改为确定性检查 |

每次编译尝试都落一条语料：`{skill, rule_id, code, text_snippet, at}`。

**验收**：语料可导出；能回答"哪类失败最多"。

### 6.7 ARS-7 信度与效度

- **信度**：两名成员对 20 个 Skill 独立打分，报 Cohen's κ（目标 ≥0.7）；
- **效度**：取 20 条历史争议结论，检验"低分档是否更常被问倒"（目标：低分档被问倒率 ≥ 高分档 1.5 倍）。

**验收**：两项都有数据表；不达标则修改口径并版本化。

### 6.8 ARS-8 跨 Skill 对比（P2）

同一分类下的 Skill 横向对比五维；只做表，不做排名结论。

## 7. 提升闭环

```
[测] ARS=46(D)
  ↓
[诊] 五维分解 → 扣分项列表
  ↓
[方] 动作库 × CU × 增益 → 排序 → 方案
  ↓
[行] 补定位 / 拆规则 / 加字段 / 补 fixture
  ↓
[测] ARS=78(B)  ← 记录 (cu, score) 点
  ↓
[语] 失败样本入库 → 下次更准
```

状态机：`draft → scored → planned → applied → rescored`。每次转移都留痕（`grade_event`）。

## 8. 改造动作库（初版）

| 动作 | 影响维 | 单次 CU | 典型增益 | 前置条件 |
|---|---|---|---|---|
| `add_locator` | L | 0.5–1 | +1.6/条 | 输出可解析 |
| `split_rule` | C | 3–5 | +2.5/条 | 有人工确认 |
| `add_field` | C、R | 2–4 | +2.0/条 | 数据源可取 |
| `add_fixture` | C | 1–2 | +0.8/条 | 已有检查 |
| `rerun_check` | R、F | 1–3 | +1.5/条 | 输入已更新 |

增益单位是"分/条"，初值由小样本拟合，之后用语料校准。

## 9. 报告规格

一页纸，四块：

1. **大字**：ARS 46 · D 档 · 12 条结论 / 10 条规则；
2. **五维条**：每维一条进度条 + 数字；
3. **扣分项**：3 条以内，每条带动作与价格；
4. **方案与预测**："34 CU → 78 分（B 档）"，附一句风险提示。

导出：`ars.json`（机器可读）+ PDF（人读）。

## 12. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | "分数是你自己定的" | 口径公开 + κ + 效度对照，三件套一起给 |
| 2 | 编译覆盖太低，C 失真 | 只报试过的样本，标 n；不做外推 |
| 3 | 改造后分数不涨 | 先在小样本校准动作库；不达预期改口径不改数据 |
| 4 | 权重被质疑（25/25/20/15/15） | 给敏感性分析：换权重后分档变化 ≤1 档 |
| 5 | 样本不足仍被打分 | 强制 warning + 分档标"参考" |

## 14. 附录

### A. 计算示例

| 维 | 值 | 加权 |
|---|---|---|
| L | 0.42 | 10.5 |
| C | 0.30 | 7.5 |
| R | 0.38 | 7.6 |
| D | 0.60 | 9.0 |
| F | 0.70 | 10.5 |
| **合计** | | **45.1 → 46（D）** |

改造后：L 0.90（22.5）、C 0.70（17.5）、R 0.80（16.0）、D 0.60（9.0）、F 0.85（12.8）= **77.8 → 78（B）**。

### B. 答辩口径

1. "这不是置信度，是覆盖率——五项都是数出来的，任何人都能复算。"
2. "46 分不是判决，是报价单：补 12 个定位、拆 3 条规则，34 CU 到 78。"
3. "这个分数会随每次改造上升，而上升曲线和失败语料，别人三个月攒不出来。"
