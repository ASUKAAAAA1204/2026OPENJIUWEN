## IR 与数值边界

`b-cmp-v1` 使用 `type=cmp`，支持 `<`、`<=`、`>`、`>=`、`==`、`!=`；左侧为非空字段名，右侧为非空字段名或数值常量。B 的运行时以 `Decimal(str(value))` 比较有限数；字段缺失返回 `INDETERMINATE / MISSING_FIELD`，非数值、布尔值、null 或非有限数返回 `INDETERMINATE / NON_NUMERIC`，不支持的 IR 返回 `INDETERMINATE / UNSUPPORTED_IR`。成功返回 `EVALUATED` 及布尔值，这只是谓词执行状态，不是第四种业务判定。

IR 常量校验目前接受 Python int / float 的有限数，不接受布尔值或数字字符串；文本编译器只识别普通十进制及百分号，先转为浮点数，可能发生精度损失或溢出；不承诺任意精度常量的跨实现一致性。操作数字段可使用可解析的有限十进制字符串。常量、非常大整数及所有特殊数值的跨实现边界尚未完整验证。

## 与 C replay 的对应及限制

在同一规则、同一证据可用且其他证据约束均满足时，B 的 true / false 分别对应 C 的 `verified` / `refuted`；输入不足或不支持应归入业务上的 `indeterminate`。C 的 `c-replay-v1` 对缺少必要证据、不能识别规则等情况返回 `None`，调用方须按证据不足处理；C 还会检查来源摘要、位置和公司绑定，因而不能把 B 的布尔输出直接当成完整业务判定。

`tests/test_b_replay_protocol.py` 对 A 的 100 个现有包及 C 复核映射比对 B 谓词和 C replay，同时检查缺来源返回 `None`；覆盖的是真实样本中出现的 `<`、`>`、`==`，不能证明全部反例或全部输入等价。C 自身 evaluator 的反例与缺证据测试另见 `tests/test_c_evaluator.py`。

C R2 当前默认 `c-claim-map-v2`，使用 B 正式规则 ID；v1 保留原字节并只读兼容。`assurance-rule-binding-v1` 的包内编译 IR 已由 replay 和独立 verifier 支持，B 复跑了现有交接 package-001 的正例和缺证据测试。旧包中的 `candidate_pending_C` 全 `<` 映射并未因此获得语义认可，不能把单包解析通过扩大成整批旧映射签收。

B 复算默认映射已随 C 切换为 v2；历史 v1 run 必须显式传入 `--claim-map fixtures/a_100/claim-map-v1.json`。映射摘要不匹配仍返回 INVALID，不自动换表。具体复核见 [C R2 复核记录](B_C_R2_复核_2026-11-05.md)。
