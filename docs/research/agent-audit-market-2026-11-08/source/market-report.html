执行摘要 / EXECUTIVE SUMMARY

「Agent 可审计」已经从技术叙事变成采购条款。2026 年 5 月至 9 月，两份标准草案与五家早期厂商同时填满了「不可篡改、可独立复算」的证据层；仍然空着的是另一半——把「证据够不够」变成可计量、可累积的债务。

  1. 需求侧出现了可引用的条款编号。2026 年 7 月 TC260 把「全量行为日志」与「高风险操作二次确认」写入智能体部署实践指南第 8 节 f、g 条；金融监管总局要求日志保存不低于业务存续期。采购不再依赖最佳实践说服。
  2. 付费方是承担后果的部门，不是使用 Agent 的团队。合规、内审、科技风险与总集信息化的预算科目才是入口；付费意愿随「是否被检查」变化，而不是随「是否上了 Agent」变化。
  3. 拦截与身份治理已被平台免费内置。Google 在 Gemini Enterprise 提供 Agent Gateway、语义治理策略与 Agent Identity/Registry；微软把 Agent ID 纳入 Entra 条件访问。决策门不构成独立卖点。
  4. 证据层已被五家厂商与两份标准同时占位。Execlave、ARKVOID、Sanna、acipta、halo-record 均发布追加写入与链式哈希的审计记录，多数只服务英文市场与单一框架。
  5. 未被定价的是证据充分性的计量。现有厂商回答「记录有没有被改过」，无人回答「证据够不够」。这是唯一仍可定义的品类，也是 2027 年主卖点的候选。
  6. 量级足够支撑一家专注型公司，不足以支撑一家平台公司。服务可得市场 4–12 亿元/年；三年可获取份额约 0.37 亿元，取决于渠道而非产品速度。

一句话结论

不要在证据链上再做一次同质化实现；在债务口径上做定义者，让证据链以标准适配器的形式存在。

01

需求侧：谁为 Agent 审计付费

DEMAND

付费方不是「用 Agent 的团队」，而是对 Agent 行为承担后果的部门。这决定了预算科目、销售路径，以及产品应被描述成什么。

把技术痛点翻译成预算语言

  • 决策过程不可见 → 事故定位靠人工复现，拉长平均恢复时间，直接计入运营损失
  • 执行前无控制点 → 损失不可逆，只能事后计提，转化为风险准备金

  • 责任无法归属 → 无法追责、无法投保、无法通过上线评审

三类常见质疑

买方会问可核验的应答
「平台已经有审计日志」日志落在平台内，可删可改，且无法在脱离平台的环境里离线复算
「可观测工具已有 trace」trace 面向调试与评测，不做链式完整性校验，保留期按厂商策略而非监管要求
「我们自建也能做」自建的主要成本在条款映射与复算工具，哈希与追加写本身只是常规工程

中型企业通常有 5–15 个生产用例，AI 合规审计项目首年预算 40 万–90 万美元，稳态 25 万–60 万美元。这一项支出属于审计与鉴证预算，与研发工具预算不在同一科目，因此不受研发降本周期直接影响。（lawr.io 2026 年成本口径 [22]）

需求侧的判断：不要卖给「想上 Agent 的团队」，要卖给「已经上了 Agent、且要被检查的部门」。前者在评估期，后者在交付期；只有后者有预算科目和截止日期。

计费单位的选择

席位定价把审计能力绑到人头，客户会按人数压价；用量定价与可观测厂商直接比价，毛利被 trace 量拖低。

按被审计对象定价，预算来源变成审计科目，价格锚点是审计服务费，而不是工具订阅。同一项能力，计费单位决定客单价，也决定销售路径。

三个口径不能相加

  • Gartner统计保护 AI 系统的支出，含安全工具、治理与合规，不等于审计证据市场

  • 因此自上而下口径只用于判断量级与趋势，SAM 由买方计数与单价推演
04

空白判断与进入壁垒

WHITE SPACE

六条变化叠加后，原来的空白被切成两半：一半已经关闭，一半仍然开着。判断哪一半值钱，取决于它是否可被计价。

已关闭

  • 哈希链 + 只追加 + 离线可验证：五家厂商与两份标准已覆盖 [8]–[12][4][15]
  • 执行前拦截与人工审批：云平台免费内置 [5]–[7][13][14]
  • 跨框架 trace 采集：可观测厂商以 OTLP 打通 [23][24]

仍然开着

  • 证据充分性的计量：没有厂商把缺口做成可累积的债务
  • 中文条款的原生映射：五家均为英文市场，未对齐 TC260 与金融监管
  • 与国产智能体底座的开箱接入：openJiuwen 生态尚无对应模块

五道壁垒的真实高度

壁垒高度依据可采取的位置
密码学与工程低链式哈希与追加写属常规工程，五家早期厂商均已实现不自研，直接对齐 AAS-1 与 IETF 字段
标准话语权高AAS-1 与 AIS-1 由外部主体维护，路线图排到 2027 年标准化轨道做一致性适配器与参考实现，争取进入测试套件
分发渠道高平台默认能力免费，独立产品需绕过平台采购嵌入 openJiuwen 与行业 AgentOS，随平台进标
合规认可中TC260 为实践指南，尚无智能体专项测评规范与测评机构共建条款对照与样例库
真实运行数据高读数可信度依赖真实样本，冷启动无样本以 shadow 期先积累不少于 100 次运行
护城河不在密码学，在 「口径 + 渠道 + 数据」。这三项都需要时间，无法用工程速度追平。

被误判为空白的三项

  • 「可法庭采信」——ARKVOID 已直接以此定位，Sanna 的 Ed25519 凭证可离线验证 [9][10]
  • 「跨框架采集」——可观测厂商已用 OTLP 覆盖主流框架，采集本身不构成差异 [23]
  • 「拦截即价值」——平台已免费提供，客户会直接回绝
05

切入路径与商业化

GO-TO-MARKET

三条路径共用同一个分发基座：以 openJiuwen 插件形态随平台进入客户环境。差别在卖什么、卖给谁、怎么收钱。

路径卖点买方收费方式主要风险
A · 合规证据包现金流一次监管检查或招标答辩即可交付的条款对照证据包持牌金融机构合规部、政企总集按被审计对象年费 + 单次出具费用与五家证据层厂商正面对撞，客户可能自建
B · 标准参考实现护城河AAS-1 与 IETF AAT 的一致性实现与测试工具审计与测评机构、平台厂商开源核心 + 一致性测试与认证服务标准不在自己手里，可能被原维护方吸收
C · 不确定债务品类把「证据够不够」变成可累积、可消解、可复核的债务投研、医疗、风控等对结论质量敏感的场景按 Skill 或按运行量订阅无监管强制力，需求教育成本高，预算科目不明确

不确定债务：唯一没有同质竞品的口径

沿依赖边传播三类标记：无证据（NO_EVIDENCE）、来源冲突（SOURCE_CONFLICT）、规格不符（SPEC_MISMATCH）。原始等级不因跳数降低；无法解析的依赖记为 UNKNOWN_DEPENDENCY。

每个缺口按 high 3 / mid 2 / low 1 计入债务，可被后续证据消解，状态只追加不覆盖；累计达阈值进入复核队列。它把「我不知道」变成一个有单位、可比较、可交付的数量。

组合与节奏

以路径 A 拿现金流，用路径 C 建品类，把路径 B 作为一年后的护城河。三者共用同一份账本 schema，不增加第二套实现。

  • 开源可观测：Langfuse、Phoenix 等未推出证据层功能，仍以 trace 与评测为主 [23]
  • 保险与承保：未发现公开条款把 Agent 审计记录作为网络风险承保条件
  • 国内测评：未见智能体专项等保或密评规范，仅有实践指南层面的文件 [1]
  • 托管账本：Amazon QLDB 已于 2025-07-31 停止支持，官方转向 Aurora 审计表设计 [29]

最强的不确定性不是技术，而是五家早期厂商尚无公开客户与融资信息，无法判断其真实推进速度。这一项应作为季度复核项，而不是一次性结论。

07

研究结论

CONCLUSION

三个判断，按确定性从高到低排列。

判断一：证据链已是入场条件，不是卖点

五家厂商与两份标准已经把「追加写入、链式哈希、离线可验证」变成行业基线。2027 年，买方会默认这项能力存在，并用它筛掉供应商；它不会再被单独计价。

判断二：仍然可定价的是「证据够不够」

现有供给只回答记录是否被改过，不回答证据是否足以支撑结论。把缺口做成有单位、可累积、可消解的债务，是唯一没有同质竞品、且能用一句话说清价值主张的位置。

判断三：速度由渠道决定，不由产品决定

平台已免费内置拦截与身份治理，独立产品必须沿平台进入客户环境。openJiuwen 插件形态既是分发基座，也是与平台厂商谈判的筹码；产品能力的边际提升，远不如渠道带来的可达性提升。

对外表述建议：「我们计量 Agent 决策的证据缺口，并把缺口变成可交付、可复核的债务。」证据链、哈希与审计账本作为实现细节出现，不作为主张。

仍需验证的三项

  • 转化率：15% 的「已上生产 Agent」比例需 30 家样本校准，误差直接决定 SAM 的高低界
  • 条款落地：TC260 第 8 节在地方检查中是否被实际引用，需 2–3 个案例确认
  • 竞品推进：五家早期厂商的客户数与融资均未公开，无法判断其真实速度
