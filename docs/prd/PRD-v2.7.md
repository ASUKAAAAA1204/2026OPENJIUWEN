## 1 背景与问题

### 1.1 业务背景

智能体已从问答型应用进入生产系统，开始执行写库、发信、下单、调用外部接口等具有副作用的动作。这类动作一旦执行，损失发生在运行时，无法通过事后评测或发布评审挽回。当前主流的可观测方案记录对话内容与调用耗时，能够回答"系统说了什么、耗时多少"，但无法回答"该动作是否应当放行、放行依据是什么、事后能否被第三方复算"。

### 1.2 现状问题

|编号|问题|具体表现|业务影响|
|-|-|-|-|
|P1|决策过程不可见|一次工具调用只留下请求与响应，缺少判定依据、参数摘要与责任主体|故障定位依赖人工复现|
|P2|执行前无控制点|异常动作在执行后才被发现，只能事后补偿|损失不可逆|
|P3|证据不可复算|证据散落在日志中，模型与参数未固化，换人或换环境无法重算|审计结论无法采信|
|P4|责任无法归属|缺少"谁批准、依据什么"的记录|无法追责、无法投保、无法通过外部审查|

### 1.3 不解决的后果

Agent 的生产使用将长期停留在低风险场景：涉及资金、数据导出、外部通信的动作必须保留人工全程接管，智能体的效率收益无法兑现；同时，出现事故时组织无法提供可核验材料，责任界定停留在口头说明。

## 2 产品定位与范围

### 2.1 定位

本产品提供两项核心能力，作用于智能体的执行过程。

**Agent 行为可审计**：每一次关键决策在执行前写入意图记录，执行后追加结果记录；两条记录以内容指纹首尾相连，只可追加、不可修改；账本自包含，不依赖链路日志，第三方可独立复算。它回答四个问题：做了什么、依据是什么、结果是什么、有没有被改动过。

**决策不确定性标记**：在账本事实之上标出证据缺口，沿依赖边向下游传播，并把未消解的缺口累积为不确定债务。它回答三个问题：证据是否足以支撑结论、缺口在哪里、累计欠了多少。

两项能力互为依据：可审计提供事实，标记在事实之上计算缺口。缺少事实，标记没有挂载对象；缺少标记，事实无法被判断是否足够。

判定与执行策略是接入手段，其作用是决定账本中「依据」一栏写入什么内容，不构成独立能力。

### 2.2 目标用户与角色

|角色|职责|主要诉求|
|-|-|-|
|平台管理员|部署、配置策略表、管理权限|控制面可用、变更可追溯|
|值班与运维人员|监控运行、处理告警|异常动作可拦截、可追溯|
|开发者|接入 Agent、排查问题|单次运行可回放、字段含义明确|
|合规与审计人员|核查控制有效性|记录完整、可独立复算|
|平台运营|管理 Skill 与版本|跨运行表现可比较|
|采购与法务|评估候选方案|同口径读数可横向对比|

### 2.3 功能范围

1. 对白名单内的 11 类决策执行同步判定，并记录判定结果与证据。
2. 生成、传播三类不确定性标记，并把未消解的标记累积为不确定债务。
3. 以追加写入方式维护账本，支持按运行回放。
4. 每次运行结束产出 8 项读数；按 Skill 维度聚合为 1 项读数。
5. 提供管理能力：发布闸、整改报价、版本对比。

## 3 目标与指标

### 3.1 产品目标

|编号|目标|验收口径|
|-|-|-|
|G1|关键决策全部产出结构化记录|按白名单 11 类计，覆盖率 100%|
|G2|未覆盖动作显式记录|记为 `UNHOOKED`，不静默通过|
|G3|三类不确定性标记可生成、可传播|缺证据、源冲突、口径不一致，分 high/mid/low|
|G4|执行前判定可阻断|规则判定段 P95 低于 50ms；纯规则、无网络、无模型调用|
|G5|判定故障不默认放行|超时或异常时按决策类处置：高危阻断或转人工，低危放行并记录降级|
|G6|账本自包含、可复算|删除 OTel 数据后仍可复算 100%|
|G7|运行边界与业务任务一致|resume 不新建运行，仅递增 `segment`|
|G8|委派可回溯且不污染父级读数|父运行记录委派关系与失败结果；聚合按决策去重，父运行自身决策照常计入|
|G9|拦截能力可控上线|shadow 期不少于 100 次运行，误报率不高于 5% 后方可开启拦截|
|G10|不确定性缺口可累积为债务|每条未消解标记计入债务并按等级加权（high 3、mid 2、low 1）；运行结束时债务值与条目数可计算、可列出；补证后对应条目标记为已消解|

### 3.3 非目标

本产品的能力边界如下。

读数衡量证据充分程度，口径由账本字段直接计算。覆盖范围为提供工具调用钩子的框架，以及经适配层接入的框架。语义判断限定在同一语言内。标记来源为账本内数据与策略表声明，模型自评不进入标记。

## 4 术语与判定口径

### 4.1 术语

|术语|取值|含义|产生方|
|-|-|-|-|
|Gate|`ALLOW` / `ASK` / `DENY` / `REWRITE`|是否放行、是否转人工、是否要求修改参数|Gate 引擎，同步、纯规则|
|Exec|`normal` / `degrade`|放行后的执行方式|策略表，仅在 `ALLOW` 或 `REWRITE` 后生效|
|Mark|`high` / `mid` / `low`|不确定性等级|标记引擎|
|Debt|加权和|未消解标记按等级加权后的累计值，可列出条目、可消解|标记引擎|
|State|`open` / `closed` / `degraded`|运行的生命周期状态|账本|

### 4.2 判定口径

Gate 输出 `ALLOW`、`ASK`、`DENY`、`REWRITE` 四类结果。`DENY` 表示不执行；`ASK` 表示转人工；`degrade` 仅用于放行后的执行策略，例如将写操作降级为只读。上述口径在接口、界面与对外材料中必须一致，不得混用。

## 5 使用场景与角色权限

### 5.1 角色权限

权限模型 v1 冻结，以下矩阵即为实现与验收依据；变更需版本号与留痕。

|能力|平台管理员|值班人员|开发者|合规审计|平台运营|
|-|-|-|-|-|-|
|查看账本|全部|全部|本人运行|全部只读|所属 Skill|
|配置策略表|可|不可|不可|不可|不可|
|切换演示开关|可|限单场景|不可|不可|不可|
|导出记录|可|可|本人运行|可|可|
|开启发布闸|可|不可|不可|不可|可|

### 5.2 核心场景

|编号|场景|前置条件|主流程|结果|
|-|-|-|-|-|
|S1|高风险写入拦截|策略表将该类动作配置为 `ASK`|调用前触发 Gate → 转人工 → 人工批准或拒绝|拒绝时动作不执行，记录为 `ASKED` 或 `DENIED`|
|S2|多 Agent 委派|父 Agent 启动子任务|父运行记录委派；子运行独立开账|父运行记录委派关系与失败结果；聚合按决策去重计数，父运行自身决策照常计入|
|S3|高风险动作降级|工具已声明只读能力，动作为查询与写入的混合调用|Gate 返回 `ALLOW`，Exec 置为 `degrade`|允许查询，拒绝写入部分|
|S4|判定故障降级|Gate 超时或异常|高危类阻断或转人工，低危类返回 `ALLOW + gate\\\_degraded`|业务不中断，高风险动作不被放行|

### 5.3 适用行业与扩展条件

本产品不针对特定行业实现，行业差异通过决策白名单与策略表表达。以下行业可按同一架构接入：

|行业|典型动作|接入条件|
|-|-|-|
|金融投研|取数、生成研报、发送邮件|补充取数与发送类决策；确认数据源可回源|
|医疗问答|检索指南、生成建议|补充检索类决策；缺证据时强制标记|
|电商客服|退款、改单、发券|补充资金类决策；配置金额阈值与人工通道|
|政企数据|跨库查询、批量导出|补充导出类决策；配置数据范围策略|
|代码 Agent|改文件、执行命令、提交|补充文件与命令类决策；启用 shell 解析|

扩展时仅新增决策类与策略条目，不修改账本结构与读数口径。

### 5.4 使用前提与限制

1. Agent 运行在提供工具调用钩子的框架内，或通过适配层接入；接入时由自检确认钩子生效，结果计入第 10.2 节评测项。
2. 白名单在接入前冻结版本，版本号写入每条决策记录；变更视为口径变更。
3. 账本追加写入、记录不可撤回；接入前完成脱敏规则配置并通过样例校验，未通过不予上线。

## 6 功能需求

### 6.1 功能总览

|编号|模块|功能说明|
|-|-|-|
|F1|决策采集|在每次工具调用前后采集动作信息，生成决策记录；未命中白名单的副作用动作记为 `UNHOOKED`。|
|F2|证据记录|为每条决策生成自包含证据记录，包含输入摘要、返回摘要、模型与参数、判定结果、时间戳与内容哈希。|
|F3|不确定性标记|依据账本内数据与策略表声明生成三类标记，按等级标注，沿依赖边传播，并累积为不确定债务。|
|F4|决策门|执行前依据策略表进行同步判定，输出四类 Gate 结果；超时或异常时按决策类处置，高危阻断，低危降级放行。|
|F5|执行策略|对已放行动作应用 `normal` 或 `degrade` 执行方式，降级仅限制动作范围，不改变判定结果。|
|F6|账本|以追加写入方式持久化决策与证据，写入前脱敏，每行生成内容哈希，支持按运行检索与导出。|
|F7|运行生命周期|按业务任务划定运行边界，支持 resume 时递增段号，支持委派关系的父子关联。|
|F8|读数与聚合|运行结束产出 8 项读数；按 Skill 维度聚合为 1 项读数，样本不足时不展示。|
|F9|回放|按运行标识重放决策序列，规则判定部分要求结果一致。|
|F10|管理能力|发布闸、整改报价、版本对比随产品交付，按角色授权开启。|

### 6.2 F1 决策采集

触发条件：Agent 发起工具调用。

处理规则：调用前读取工具名与参数，匹配白名单；命中则创建决策记录并进入 F4；未命中但工具声明为副作用动作（登记字段 `side_effect=true`）则记录为 `UNHOOKED`，不进入判定，并计入未覆盖率。调用完成后追加返回摘要与耗时（见 6.7 两段写）。

输出：决策记录，字段见第 7.2 节。

边界与异常：工具调用被框架跳过时，跳过数量计入未覆盖率，超过阈值触发告警；参数无法脱敏时动作不执行，记为 `DENIED`，原因记为无法脱敏。

### 6.3 F2 证据记录

触发条件：决策记录创建成功。

处理规则：采集输入快照摘要、工具返回摘要、模型标识与参数、判定结果、时间戳，计算内容哈希后写入。

输出：证据记录，与决策记录一对一关联。

边界与异常：返回内容为空时仍生成记录，标记为空证据；证据体超过存储阈值时仅保留摘要与内容寻址引用。

### 6.4 F3 不确定性标记

|标记|触发条件|判据来源|默认等级|
|-|-|-|-|
|`NO\\\_EVIDENCE`|决策无关联证据或证据为空|账本|命中高危决策类时为 high，其余为 mid|
|`SOURCE\\\_CONFLICT`|同一断言的两个来源不一致|回源比对，仅对带来源的动作|mid|
|`SPEC\\\_MISMATCH`|实际参数与策略表声明不一致|策略表与参数摘要|可换算时为 low，否则为 mid|

传播规则：仅在"下游引用上游输出"的依赖边上传播；原始等级不因跳数降低，衰减仅作用于下游的「影响呈现」，最低为 low；依赖边缺失时记 `UNKNOWN_DEPENDENCY` 并保持原等级。单次运行的标记密度上限为 100%。

边界与异常：依赖边缺失时记 `UNKNOWN_DEPENDENCY` 并保持原等级，不静默去除；回源不可达时不判定为冲突，记为缺证据。

**债务累积**：未消解的标记计入债务。权重取等级值：high 记 3，mid 记 2，low 记 1。每条债务条目关联一个决策、一个标记类型、一个权重、一个状态，以及消解时引用的证据。

**消解**：补证消解 `NO_EVIDENCE`；统一来源消解 `SOURCE_CONFLICT`；修正参数并重新过闸消解 `SPEC_MISMATCH`。消解只追加状态并保留原始条目，原始记录不删除、不改写。

**合并**：同一运行内按决策标识去重求和。委派场景下父运行汇总子运行的债务并单独列出，聚合时不重复计入。

**触发**：运行结束时债务值与条目数写入运行读数；单次运行债务值达到策略表阈值时，该运行进入复核队列。

### 6.5 F4 决策门

处理规则：读取策略表中该决策类的规则，按参数摘要匹配，输出 `ALLOW`、`ASK`、`DENY` 或 `REWRITE`。`REWRITE` 需给出修改后的参数；改写结果必须重新过闸，最多重判 2 轮，仍未通过则 `DENY`，改写后的实参摘要写入 `args_after`。`ASK` 默认等待 30 秒，人工应答后放行或拒绝；超时按策略表的 `ask_timeout_policy` 处置：高危类默认 `DENY + TIMEOUT`，低危类可配置放行。

性能约束：规则判定段 P95 低于 50ms（ASK 人工等待不计入）；不联网、不调用模型、不依赖 OTel 导出。

边界与异常：策略表缺失该类规则时按 `DENY` 处置并记录规则缺失；Gate 异常时按决策类处置，高危阻断、低危放行并标记降级。

### 6.6 F5 执行策略

处理规则：对 `ALLOW` 与 `REWRITE` 后的动作应用执行方式。`degrade` 仅对白名单中已声明只读能力的工具生效，被限制部分需返回明确原因；工具在登记时声明能力类型（`read_only` / `mixed` / `write`），声明随白名单版本冻结。未声明只读能力的混合调用不得返回 `ALLOW`，应按 `ASK` 或 `DENY` 处置。

边界与异常：降级后仍失败时按普通失败处理，不重复判定。

### 6.7 F6 账本

账本是一份只能往后写、不能回头改的操作流水，用来回答“当时发生了什么、凭什么放行”。

**记什么**：每次工具调用分两段写。执行前写一条「意图」记录：属于哪个任务、调用了什么工具、参数摘要、Gate 结果是放行、转人工、拒绝还是改写、判定理由与耗时、本次执行标识。执行后追加一条「结果」记录：输入和输出各留一份摘要、用的是哪个模型和参数、实际执行方式、结束状态、发生时间、这条记录自身的指纹。两条记录共用同一个决策标识，结果通过追加写入产生，不修改意图记录。进程在两段之间崩溃时，重启后扫描超过 60 秒仍无结果的意图记录，标记为 `UNKNOWN_OUTCOME` 并进入复核队列。

**怎么保证没被改过**：只追加，不修改，不删除。每条记录都带上一条的指纹（内容哈希），首尾串成一条链。改动中间任意一条，其后的记录全部对不上；尾部截断由每日签名检查点（头部哈希与记录长度）检出。

**脱敏**：账本长期保存，写入前先把手机号、密钥、内部地址等敏感内容替换掉。记录一旦写入就无法撤回，所以脱敏是写入的前提条件，不能留到事后补做。

**怎么用**：按任务查一次运行的完整过程；按决策类型或时间段批量查；按条件导出给审计或复核方。

**出错怎么办**：写入失败先重试；重试仍失败就报警，并明确记录“哪条丢了”，不允许静默丢弃。账本不依赖链路日志——链路日志默认只保留 7 天，清理后账本仍能独立读取和复算。

### 6.8 F7 运行生命周期

规则：一个业务任务对应一个运行；运行标识由任务标识派生，不随进程或对话轮次变化；resume 时递增段号；委派产生的子任务独立开账，父运行仅记录委派关系与失败结果。

输出：运行记录，含状态、起止时间、段号、委派关系。

边界与异常：同一任务重复启动时按任务标识去重；委派深度上限为 3，超限直接 `DENY`。

### 6.9 F8 读数与聚合

运行读数在运行结束时立即产出，共 8 项：声明一致率、证据完整率、复现率、回放一致率、时效有效率、标记密度、处置执行率、不确定债务。计算口径如下，分母为 0 时该读数记「不适用」，不参与聚合：

|读数|分子|分母|
|-|-|-|
|声明一致率|实际参数与策略表声明一致的决策数|有声明可比对的决策数|
|证据完整率|证据记录字段齐全（见 7.2）的决策数|全部决策数|
|复现率|重放后判定结果一致的决策数|全部决策数（缺证据计为未复现）|
|回放一致率|规则判定部分回放一致的决策数|规则判定部分的决策数|
|时效有效率|证据采集时间与动作发生时间偏差不超过 5 秒的决策数|全部决策数|
|标记密度|带至少一类标记的决策数|全部决策数|
|处置执行率|按 Gate 结果完成处置的决策数（`DENY` 未执行、`ASK` 已应答并按结果执行均计为已处置）|应处置决策数|
|不确定债务|未消解标记按等级加权求和（high 3、mid 2、low 1）|不适用（直接登记数值与条目数，无分母）|

Skill 读数由运行读数聚合，口径如下：

|参数|口径|
|-|-|
|计数单位|按决策标识去重后计入所属运行；父运行自身的决策计入父运行并参与聚合，仅无自身决策的纯编排运行不计入样本|
|滚动窗口|最近 20 次有效运行；有效指至少包含 1 个白名单决策|
|加权方式|等权平均，不按决策类加权|
|最小样本|样本数不少于 5 且覆盖不少于 3 个决策类|
|展示方式|只展示读数与样本量，不设 A/B/C/D 分档|

样本不足时展示"样本不足"及实际样本数与覆盖类数。

### 6.10 F9 回放

规则：按运行标识读取决策序列，按原顺序重放。规则判定部分要求结果一致；模型输出部分不要求文本一致，仅比对结构化字段。

边界与异常：证据缺失的决策在回放中标注为不可复现，保留在分母内计为未复现，并单独报告可评估覆盖率。

### 6.11 F10 管理能力

|能力|启用方式|输出|
|-|-|-|
|发布闸|默认关闭，开启即生效|通过或阻断，附判定理由|
|整改报价|默认关闭，开启即生效|按条报价|
|版本对比|默认关闭，开启即生效|两个版本的读数差|

### 6.12 状态流转

运行状态：`open`（已创建，可写入）→ `closed`（正常结束，只读）。判定降级发生时标记 `degraded`，运行仍可继续写入。

决策事件：`GATE_DECIDED`、`ASK_REQUESTED`、`ASK_ANSWERED`、`EXEC_STARTED`、`EXEC_FINISHED`、`EXEC_FAILED`。事件只追加、不可变更，同一决策标识下按时间排序。

决策状态由事件派生，是只读视图：`ALLOWED`、`ASKED`、`DENIED`、`REWRITTEN`、`UNHOOKED`、`TIMEOUT`、`UNKNOWN_OUTCOME`。结果回填通过追加 `EXEC_FINISHED` 或 `EXEC_FAILED` 事件实现，不修改既有事件。

Gate 结果与决策状态的对应：

|Gate 结果|决策状态|
|-|-|
|`ALLOW`|`ALLOWED`|
|`ASK` 未应答|`ASKED`|
|`ASK` 拒绝|`DENIED`|
|`ASK` 超时|`TIMEOUT`（高危类同时不执行）|
|`DENY`|`DENIED`|
|`REWRITE`|`REWRITTEN`|
|未命中白名单|`UNHOOKED`|
|Gate 故障（低危）|`ALLOWED`，标记 `degraded`|
|Gate 故障（高危）|`DENIED`，标记 `degraded`|

### 6.13 异常与边界汇总

|场景|处理方式|
|-|-|
|Gate 超时|按决策类处置：高危 `DENY + TIMEOUT`，低危 `ALLOW + TIMEOUT`；记录超时原因|
|Gate 异常|按决策类处置：高危阻断，低危 `ALLOW + gate\\\_degraded`，计入降级率|
|证据缺失|生成 `NO\\\_EVIDENCE` 标记，不阻断|
|白名单未命中|记 `UNHOOKED`，动作照常执行但必须记账；计入未覆盖率并告警|
|账本写入失败|重试后告警，不静默丢弃|
|参数无法脱敏|动作不执行，记为 `DENIED`，原因记为无法脱敏|
|委派超深|直接 `DENY` 并记录|
|运行重复启动|按任务标识去重|

### 7.3 传播规则

标记仅在依赖边上传播。原始等级不因跳数降低，下游按「影响呈现」逐跳衰减，最低为 low，不归零。依赖边缺失记 `UNKNOWN_DEPENDENCY` 并保持原等级。单次运行的标记密度上限为 100%，避免全链同时降级而失去区分度。

债务按条目累积：每条未消解标记是一条债务，权重取等级值；同一决策的多类标记分别计条。运行结束时按运行求和并登记。委派场景下父运行汇总子运行债务，聚合时按决策标识去重。消解只追加状态，原始条目的类型与权重保持不变。

### 7.4 断言记录与决策的关联

断言记录与决策记录分表存储。两者约束不同：决策记录必须包含判定结果与参数摘要，断言记录必须包含定位与来源；合表会导致双方字段大面积空缺且无法分别校验。两者关系为一对多，一次查询可能产出多条断言。

抽取到断言但找不到对应决策时，记录为 `MISSING_DECISION`，状态为「风险未知」：生成 `NO_EVIDENCE` 标记（等级 high），计入声明一致率分母与缺证据统计，并进入复核队列。该情形不得按无风险处理。

## 8 接入与系统约束

### 8.1 接入形态

|形态|接入点|返回值|
|-|-|-|
|进程内 Agent|工具调用前钩子|修改调用参数或跳过调用|
|外部 Agent|Hook 分发器|`ALLOW` / `DENY` / `REWRITE` / `ASK` / 提供方策略|

两类接入共用同一份策略表。所有工具调用经过统一执行入口，该入口支持跳过执行，判定必须挂在该入口上。

### 8.2 硬约束

1. Gate 不依赖 OTel 导出器。导出器存在批量、丢弃与不重试行为，不能作为判定依据。
2. OTel 关闭时 Gate 仍可工作。
3. Gate 判定不联网、不调用模型。
4. 账本不依赖 OTel 数据，`trace\\\_ref` 仅为弱引用。

### 8.3 存储分层

|数据|介质|保留策略|是否允许丢失|
|-|-|-|-|
|OTel 链路数据|按天切分的文件|默认 7 天|允许|
|账本|追加写入数据库|永久|不允许|
|证据快照|账本内联或内容寻址文件|随账本|不允许|

链路引用悬空为允许状态，不影响账本读取与复算。

## 9 非功能需求

### 9.1 性能

Gate 判定 P95 延迟低于 50ms（仅规则判定段）；判定过程不得引入网络请求与模型推理。意图记录在工具调用前落盘，结果记录在执行后追加；两段写入的 P95 均不超过 5ms，且不得阻塞工具调用返回；异步队列积压超过 1000 条时告警。

### 9.2 可靠性

Gate 故障按决策类处置：高危阻断、低危放行并标记；账本写入失败必须告警，不允许静默丢弃；进程重启后账本可继续追加，运行可按标识恢复。

### 9.3 安全与合规

账本永久保留，写入前必须完成脱敏，覆盖个人信息、凭据与内部地址；脱敏规则随策略表版本化，变更留痕。账本读取按角色隔离，导出行为记入审计记录。记录不得包含可用于重建原始凭据的字段。

### 9.4 兼容与可运维

锁定 openJiuwen 0.1.20.post1；框架升级需重跑第 10.2 节评测项。策略表为只读配置，支持版本号与变更记录，回滚通过切换版本完成。

## 11 风险与缓解

|风险|影响|缓解措施|
|-|-|-|
|钩子语义缺口，如命令内部写、子进程写、外部工具内部写|覆盖率虚高，分母不可信|用命令解析拆分判定；无法判定的一律按 `ASK` 转人工，不设排除项|
|框架按轮次生成会话标识|resume 被切成多段|运行标识绑定业务任务，轮次标识仅作段号|
|Gate 同步故障|Agent 全链路阻塞|超时与异常按决策类处置：高危阻断，低危放行并计入降级率|
|OTel 默认保留 7 天|链路引用悬空|账本自包含，引用仅作弱关联|
|个人信息进入账本且不可撤回|合规风险|写前脱敏作为写入前置条件|
|循环委派|账本无限增长|委派深度上限 3，按任务去重|
|框架版本漂移|接口变更导致判定失效|锁定版本，升级须重跑评测项|

委派规则：责任链可回溯，但不回滚上级读数；深度上限 3，超限直接拒绝；聚合按决策去重计数，父运行自身的决策照常计入。
