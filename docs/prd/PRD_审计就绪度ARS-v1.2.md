| 项 | 内容 |

## 0. 定位

ARS 不验证结论，它度量**结论能不能被验证**。

在四性模型里，可观测/可追溯/可问责都已有归属，**可验证是空位**。ARS 补的就是这一格：

> 前三性证明"发生过什么"，第四性证明"结论能不能被独立检验"。

### 0.1 评分坐标——不是 f(skill)，是 f(skill_version, model, data_profile)

同一个 Skill 换模型、换数据，分数会变——因为输出格式变了，可定位率就变。**报告里必须写"某 Skill 在某模型、某数据画像下的 ARS"**，不写这三个分数不可比。

### 0.2 两段 ARS 夹着链路——不是串行前置

```
规则集 ──[ARS_d：只算 C]──► 设计预警（C < 0.5 标低分，不阻断）
                                   │ 确认继续
                                   ▼
                     链路八段（S2→S5 产证据，产完不打分）
                                   │
                                   ▼
                     [ARS_r：只算 L、R、D、F] ──► 发布闸（ARS ≥ 70）
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
                 放行                         改造方案
                                                  │ 改规则
                                                  ▼
                                        回到 ARS_d 重算（ARS_g 治理态）
```

|落点|何时|算哪几项|依赖链路吗|
|---|---|---|---|
|**ARS_d 设计态**|S0/S1 之后，**跑之前**|C|**不依赖**——C 在规则写下时就能算|
|**ARS_r 运行态**|S4/S5 之后|L、R、D、F|依赖|
|**ARS_g 治理态**|改造后重测|全部|依赖（前后对比）|

**反直觉的一点**：设计态只算 C，不需要跑一次就能给出。L 需要 claim 的 locator 回源结果，而 claim 是 S2 运行产物，因此 L 归运行态。设计预警不是硬门禁，只是"这包规则先天不足"的提前提示。

### 0.3 对象层级

|对象|层级|操作|
|---|---|---|
|结论（claim）|**审计原子对象**|单条：有/无 locator、能否复算|
|一次运行（run）|测量单位|R、D、F 维度在这一层才有意义|
|Skill @ 版本|**评分稳定可交易单位**|ARS 主坐标，可发布/采购/上架|
|发布版本（release）|闸门拦截单位|在这层卡住才有意义|

## 1. 问题

### 1.1 三个买家的同一句话

| 买家 | 他问的问题 | 现在得到的回答 |
|---|---|---|
| 平台运营 | 这个 Skill 能不能上架 | "跑分不错"（跑分不解释可审计性） |
| 企业采购 | 买回来能不能过审 | "有日志"（有日志 ≠ 能复核） |
| 技术负责人 | 上线前还要补什么 | 说不清，只能等出事 |

**共同点**：都在问"能不能审"，而现有工具都在答"跑了什么"。

### 1.2 为什么现有工作不解决

七项工作（LEDGER / ClaimReceipt / SSEG / VeriHarness / 2610.01348 / AFT / AAT）全部度量**单次输出的质量**。ARS 度量的是**跨 Skill、跨时间的可验证性属性**，且它必须能在跑之前给出——这是它们结构上做不到的。

## 2. 目标与非目标

| # | 目标 | 判据 |
|---|---|---|
| A1 | 可复算 | 第三方拿数据能算出完全相同的分 |
| A2 | 可解释 | 每个扣分项有数字 + 一句人话 + 对应动作 |
| A3 | 可提升 | 执行方案后实际增幅 ≥ 预测的 70% |
| A4 | 可拦截 | 低于阈值时能在发布流程里卡住 |
| A5 | 会复利 | 语料随使用增长，且能展示增量 |

**非目标**：不预测正确率、不做单条结论的对错裁决、不做跨组织认证、不承诺"通过某标准"。

## 3. 使用场景

### S1 上架前（平台运营）

跑一次 → 得到 ARS 与五维分解 → 决定是否上架 / 退回改造。

### S2 采购前（企业）

对候选 3 个同类 Skill 各算一次 → 对比五维 → 用"到 B 档要多少 CU"做决策，而不是只看跑分。

### S3 发布前（技术负责人）

把发布闸接进流水线：ARS < 70 阻断；允许带豁免发布，但豁免需记 `accept_with_grade`。

## 4. 评分模型

### 4.1 坐标与三段

**评分坐标**：`ARS = f(skill_version, model, data_profile)`。报告必须带三元组，不写则分数不可比。

**三段各算各的，最终在发布闸合成**：

|段|算哪几项|权重分配|合成方式|
|---|---|---|---|
|**ARS_d 设计态**（S0/S1 后，跑之前）|C|25 满 | 直接出分项，不等 r 态；只作设计预警|
|**ARS_r 运行态**（S4/S5 后）|L、R、D、F|25 + 20 + 15 + 15 = 75 满 | 直接出分项|
|**ARS_g 治理态**（改造后重测）|全部 L+C+R+D+F|100 满 | 与改造前 ARS 对比，出提升曲线|

**总 ARS（发布闸用）**：C×25 + L×25 + R×20 + D×15 + F×15，运行态算完后合成。

### 4.2 五个分项

| 代号 | 名称 | 定义 | 权重 | 归属段 |
|---|---|---|---|---|
| L | 可定位率 | **回源解析成功**的 locator / 总 claim（声明精确但解析失败不计） | 25 | r 态 |
| C | 可编译率 | 编译通过**且 fixture 三条全绿**的规则 / 总规则 | 25 | d 态 |
| R | 可复算率 | **独立 verifier 重算一致**的 claim / 总 claim（"有证据"不算通过） | 20 | r 态 |
| D | 确定性率 | **同输入两次运行结果一致**的检查 / 总检查；fixture 通过只作前置，不算确定性 | 15 | r 态 |
| F | 新鲜度 | **全部证据 fresh 的 claim** / 总 claim（不按证据条数计） | 15 | r 态 |

```
ARS（总，发布闸用）= 0.25C  ← ARS_d 段计算，跑之前就能出
                    + (0.25L + 0.20R + 0.15D + 0.15F)  ← ARS_r 段计算，跑之后出
```

### 4.3 归一化与边界

| 情况 | 处理 |
|---|---|
| 分母为 0（如没有规则） | 该项记 `NA`，权重按**同段内剩余项**重分配，并在报告注明；跨段不重分配 |
| 样本 < 10 | 文档级 `PARTIAL`：只报分项，**不出总分与分档** |
| 任一维 `MISSING` | 文档级 `PARTIAL`：只报分项，**不出总分与分档** |
| 证据包缺失 | 该 claim 计入 R 的分子 0、分母 1（按未通过计，不得剔除） |
| 过期但已重验 | 以重验后的 digest 为准 |
| r 态未跑且 C=VALUE | 文档级 `DESIGN_ONLY`：只报 C 分项；C 本身 MISSING/NA 则走 PARTIAL |

### 4.4 分档

| 档 | 区间 | 含义 |
|---|---|---|
| A | ≥ 85 | 可直接发布 |
| B | 70–84 | 可发布，需记录遗留债务 |
| C | 50–69 | 需改造后发布 |
| D | < 50 | 不允许发布 |

**只报整数与分档，不报小数。** 小数会制造不存在的精度。

### 4.5 红线

- 不得称其为"置信度""正确率""可信度分数"；
- 不得由 LLM 直接打分（必须由五项计数算出）；
- 不得在样本不足时不标注；
- 设计态 ARS_d 只算 C，不得偷偷调用链路数据；L 只能在运行态回源计算；
- **未回源解析的 locator 不得计入 L**（声明"精确"不算）；
- **R 不得由被测方自证**，必须经独立 verifier；
- **不得在 `PARTIAL` 状态下给总分**；
- 报告标题栏必须显示三元组坐标：`skill@version · model · data_profile`。

## 5. 数据来源与可算性

| 维 | 数据来源 | 计算时机 | 归属段 | 缺失时 |
|---|---|---|---|---|
| L | 输出解析的 locator（S3 运行后回源） | **运行后** | r 态 | 视为不可定位 |
| C | 规则编译结果（S0/S1） | **设计期** | d 态 | 视为不可编译 |
| R | 独立 verifier 全量复算（S4/S5；生产 10% 抽样） | **运行后** | r 态 | 计入未通过 |
| D | 同输入双跑一致性（S4） | **运行后** | r 态 | 视为不确定 |
| F | digest 比对（S3） | **每次运行** | r 态 | 视为过期 |

**关键**：C 在设计期就能算，这让 ARS_d 能当**设计预警**用；L/R/D/F 必须等运行，这让 ARS_r 能当**发布闸**用。两段分离是本产品结构上最关键的设计决策；L 归运行态是本轮修正的核心。

## 6. 功能需求

### 6.1 ARS-1 打分器

**输入**：证据包集合 + 规则编译结果 + 检查记录。
**输出**：`{score, band, dims:{L,C,R,D,F}, n_claims, n_rules, n_checks, warnings[]}`。
**规则**：严格按 §4.1；`N/A` 重分配；样本不足打 warning。

**验收**：第三方脚本复算，差异 = 0；`warnings` 覆盖所有边界情况。

### 6.2 ARS-2 扣分解释器

**输出**：每个分项一句人话 + 一个数字 + 一个动作指针。

示例：
> **可定位率 0.45**：20 条结论里 9 条有精确到行的定位，11 条只有文件名。
> → 补定位（约 0.7 CU/条）

**验收**：任一分项点开 ≤2 层可达具体条目列表。

### 6.3 ARS-3 改造方案器

**输入**：扣分项 + 动作库 + CU 单价。
**输出**：按"分/CU"降序的动作列表 + 目标档 + 总价 + 预期分。

```yaml
plan:
  current: 47
  target_band: B          # 用户指定，默认 B
  actions:
    - {act: add_locator,  n: 9, cu: 6.3,  gain: 11.25}
    - {act: rewrite_rule, n: 4, cu: 12.0, gain: 11.71}
    - {act: add_field,    n: 4, cu: 8.0,  gain: 4.00}
    - {act: rerun_check,  n: 4, cu: 4.0,  gain: 4.00}
    - {act: rerun_stale,  n: 2, cu: 2.0,  gain: 1.50}
  total_cu: 34.0
  predicted: 79
```

**算法**：贪心——每轮取 `gain/cu` 最高的动作，直到达到目标档或边际枯竭（<0.5 分/CU）。
**验收**：预测与实际重测偏差 ≤30%（A3 放宽到 70% 兑现率）。

### 6.4 ARS-4 重测与曲线

- 执行动作后自动重测，记录 `(cu, score)` 点；
- 画提升曲线（当前点 + 目标档线）；
- 支持"预算上限"模式：给定 CU，输出能达到的最高分。

**验收**：一条命令重跑出同一张图。

### 6.5 ARS-5 闸门：1 硬闸 + 2 约束

| 名称 | 位置 | 规则 | 输出 |
|---|---|---|---|
| **设计预警** | S1 之后 | C < 0.5 → 低分提示，`design_ack` 确认继续 | 不阻断；记确认人/时间 |
| **发布闸** | S6 | ARS < 70 → 阻断 | 阻断 + 方案报价；`waiver` 才放行 |
| **预算闸** | S6 | 预算耗尽 | `accept_with_grade` + 原因码 |

设计预警不是闸门，不产生 waiver；发布闸的豁免必须落 `waiver`（谁、何时、理由、有效期）。

**验收**：发布闸可拦截；设计预警与预算约束各有可演示场景；豁免可查。

### 6.6 ARS-6 编译失败分类法 + 语料

四类失败码：

| 码 | 含义 | 典型动作 |
|---|---|---|
| `NO_LOCATOR` | 规则引用的事实没有可定位字段 | 补 locator |
| `SUBJECTIVE_RULE` | 规则含"合理/适当/良好"等不可判词 | 拆成可判谓词 |
| `MISSING_FIELD` | 规则要求的输入不存在 | 补字段或降级规则 |
| `NON_DETERMINISTIC` | 判定依赖 LLM 或随机 | 改为确定性检查 |

每次编译尝试都落一条语料：`{skill, rule_id, code, text_snippet, at}`。

**验收**：语料可导出；能回答"哪类失败最多"。

### 6.7 ARS-7 信度与效度

- **信度**：两名成员对 20 个 Skill 独立打分，报 Cohen's κ（目标 ≥0.7）；
- **效度**：取 20 条历史争议结论，检验"低分档是否更常被问倒"（目标：低分档被问倒率 ≥ 高分档 1.5 倍）。

**验收**：两项都有数据表；不达标则修改口径并版本化。

### 6.8 ARS-8 跨 Skill 对比（P2）

同一分类下的 Skill 横向对比五维；只做表，不做排名结论。

## 7. 提升闭环

```
[测] ARS=47(D)
  ↓
[诊] 五维分解 → 扣分项列表
  ↓
[方] 动作库 × CU × 增益 → 排序 → 方案
  ↓
[行] 补定位 / 原地改写规则 / 加字段 / 补 fixture
  ↓
[测] ARS=79(B)  ← 记录 (cu, score) 点
  ↓
[语] 失败样本入库 → 下次更准
```

状态机：`draft → scored → planned → applied → rescored`。每次转移都留痕（`grade_event`）。

## 8. 改造动作库（初版）

| 动作 | 影响维 | 单次 CU | 典型增益 | 前置条件 |
|---|---|---|---|---|
| `add_locator` | L | 0.7 / 条 | +1.25 分/条（9 条 +11.25） | 输出可解析、源可回源 |
| `rewrite_rule`（原地改写，含 1 check + 3 fixture） | C、D | 3.0 / 条 | +2.93 分/条（4 条 +11.71） | 有人工确认；**不新增规则条数** |
| `add_field` | R | 2.0 / 条 | +1.00 分/条（4 条 +4.00） | 字段已在源里，只需映射 |
| `rerun_check` | R、F | 1.0 / 条 | +1.00 分/条（4 条 +4.00） | 输入已更新、检查可跑 |
| `rerun_stale` | F | 1.0 / 条 | +0.75 分/条（2 条 +1.50） | 过期证据可重新采集 |

两点必须写死：

1. **`rewrite_rule` 是原地改写，不是拆规则**——`n_rules` 恒为 10；改写后该规则从"不可编译"变"可编译"，同时新增 1 个 check + 3 个 fixture，`n_checks` 10 → 14。单价 3.0 已含 check 与 fixture，不另计费。
2. **`add_field` 与 `rerun_check` 作用于互不重叠的 claim 组**（#10-13 与 #14-17）。若重叠，R 只 +4，总分掉到 74。

增益单位是"分/条"，初值由小样本拟合，之后用语料校准。

## 9. 报告规格

一页纸，四块：

1. **大字**：ARS 47 · D 档 · 20 条结论 / 10 条规则 / 14 个检查；
2. **五维条**：每维一条进度条 + 数字（L 9/20 · C 3/10 · R 8/20 · D 6/10 · F 15/20）；
3. **扣分项**：3 条以内，每条带动作与价格；
4. **方案与预测**："34 CU → 79 分（B 档）"，附一句风险提示。

导出：`ars.json`（机器可读）+ PDF（人读）。

## 12. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | "分数是你自己定的" | 口径公开 + κ + 效度对照，三件套一起给 |
| 2 | 编译覆盖太低，C 失真 | 只报试过的样本，标 n；不做外推 |
| 3 | 改造后分数不涨 | 先在小样本校准动作库；不达预期改口径不改数据 |
| 4 | 权重被质疑（25/25/20/15/15） | 给敏感性分析：换权重后分档变化 ≤1 档 |
| 5 | 样本不足仍被打分 | 硬规则：样本 <10 或任一维 MISSING → 文档级 `PARTIAL`，只报分项，不出总分与分档 |

## 14. 附录

### A. 计算示例（三元组坐标：`skill@inv-daily-v1.2.0 · gpt-5-mini · industry.csv:150行`）

**原始态（ARS_d 先出，不等 r 态）**：

## 15. 变更记录（2026-10-30）

### 15.1 起因：三项失真 + 一处自证

| 问题 | 证据 | 影响 |
|---|---|---|
| D 恒为 1.0 | 两个 checker 硬编码 `is_deterministic=True` | 虚高 15 分 |
| F 口径错 | 按证据条数算，PRD 要求按 claim | 挂多条证据的 claim 被放大 |
| R 近似占位 | "有 evidence 就 VERIFIED" | R 退化为"有没有证据" |
| 度量自证 | locator 由被测方声明、不回源 | "第三方可复算"不成立 |

### 15.2 抗博弈 ARS-9（全部用绝对条数，不用比率）

| 机制 | 做法 | 判定（20 条样本下） |
|---|---|---|
| H1 held-out | 20 条 claim 中的 5 条不展示给 Skill 作者 | held-out 与上报 L **相差 ≤2 条**，否则整份报告标"待核" |
| H2 抽查 | locator 人工回源（demo 全量，生产 10%） | 一致率 ≥95% |
| H3 真实性差 | `resolved` 条数与 L 分子并列上报 | `L 分子 − resolved 条数 ≤3`（≈0.15×20） |
| H4 涨分/涨真实 | 改造后 L 涨、resolved 不涨 | L +9 而 resolved +0 → 标 `gaming`，不计该次增益 |
| H5 拆分检测 | 等价琐碎谓词不计 C 增益 | 人工抽检 10 条，命中即回退该规则 |

> 旧版 H3/H4 用比率比较（`resolved_rate` vs L），在"L 涨、resolved 不动"时存在逻辑不可能触发的问题；本轮改为绝对条数差，可直接判定。
