# M0成员签收材料约定

A不生成B/C/D通过签收。各成员提供自己的B.json、C.json或D.json，包含reviewer_role、reviewer、status、scope、evidence数组；每条证据包含项目相对path和sha256。缺材料、缺身份、状态非PASS、路径越界、文件缺失或哈希不符均不通过。

B范围：三框架精确版本/环境兼容、36场景108执行及9次真实模型证据；C范围：16项冲突独立审查、冻结测试清单及回归复核；D范围：现有verify、启动停止3轮、CI必需门禁与失败注入。

机器校验仅证明材料结构与文件完整，不能替代A对具体场景、样本、失败分支及当前源码的实质审查。不得仅填写PASS或引用历史不对应范围的交接文档。源码变化后重新核验对应范围。

签收必须包含source_sha256，与audit.py输出的当前源码摘要一致；requirements须包含该角色完整必需范围（具体键见audit.py）。源码变化后旧材料自动失效。要求键齐全只代表声明覆盖，最终仍需人工逐项复核原始运行结果，不得通过填写键名代替测试。
