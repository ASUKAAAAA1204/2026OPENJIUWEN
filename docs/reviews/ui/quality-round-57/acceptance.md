# 第五十七轮：提交入口清单、执行恢复与同页互斥

I03前端审计覆盖以下9组入口，区分提交等待、服务拒绝和结果未知，不将取消等待称为撤销服务端操作。

|入口|前端防重复与恢复依据|
|---|---|
|创建/关闭/恢复运行|同步busy、范围确认、任务/段号/修订/回执绑定、结果未知锁定，创建可按原任务查询|
|Agent启动/续读|busy、先读授权执行状态、状态修订绑定、沿用request_id与事件游标；刷新恢复原请求，不重新调度|
|批准/拒绝审批|版本/参数/范围/时限核对，pending/到期/权限保护，未知结果刷新确认|
|债务消解|证据范围确认、原条目校验、未知结果锁定；修改证据或重判引用清除旧确认|
|管理配置3项、发布评估、报价|启用/权限/快照及范围确认、同步submitting、冲突后刷新；配置操作不冒充发布/订单|
|策略切换/回滚|版本与指纹绑定、范围确认、busy/stale保护；与会话操作双向互斥|
|登录/退出|submitting、密码不存储、未知结果先读取会话，成功重新加载清理账号数据|
|授权导出|busy、范围确认、文件/运行/审计核验，不自动重放；人工再次申请是新一次授权导出|
|只读回放|busy、原快照绑定、execute_tools=false；失败先刷新核对，不自动重放|

跨页工作台保护由operationBusy聚合，阻止提交时的导航与刷新；beforeunload只能请求浏览器标准提示，不能保证拦截强关或持久保存响应。服务端幂等、互斥、权限及结果查询仍是最终保障。只读回放与导出有授权/审计请求，但不会执行原工具；人工重试不能等同再次执行原业务动作。

本轮修复执行面板刷新后默认为idle的风险。新增GET execution-state草案与类型校验，初次打开或段变化先读取服务端事实；只有idle显示启动。active/unknown恢复原request_id，由用户续读；completed/failed/review不提供新启动。查询失败不回退idle。新启动携带expected_execution_revision，服务端需原子核对；已有请求续读优先幂等，不能因修订变化重开任务。恢复连接被403拒绝仍保留原结果待核对，不能断言原任务失败。此前输出未在浏览器存储，页面明确提示，完整结果需查账本。

另修复债务证据范围修改后沿用旧确认，以及退出登录等待期间仍可提交当前策略表单的问题。策略与会话双向锁定，提交函数再检查locked，完成后不恢复旧确认。
