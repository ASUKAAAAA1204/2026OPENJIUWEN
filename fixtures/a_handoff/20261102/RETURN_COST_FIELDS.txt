成本与模型调用回传字段说明
适用：B/C → A 的执行记录；配套 return_templates/COST_RECORD_TEMPLATE.json。
该模板用于交换实测信息，不是新增的冻结事件模型，也不直接替代 AgentEvent 或 CostCalculator 的输入。

一、最少需要回答的问题

哪个版本、哪次运行、哪个实际操作、作用于哪些 claim；做了多久；有没有调用模型；用了多少输入/输出 token；有没有人工处理；这个操作是否已经包含在其他成本里。
可按 JSONL 每行一条操作记录返回，也可给 JSON 数组。保留原始调用/计时证据及其相对路径，A 收到后按双方确认的口径转换汇总。
方案里的预测价、演示参考价和真正的执行记录分开。模板只收实测，不将“预计 1 CU”填成测量值。

二、字段含义与填写要求

run_id：本次运行唯一标识；与原始记录一致。
operation_id：本次具体操作的唯一标识；用于避免重复计费。失败重试用不同标识并记录它们的关系。
owner：B 或 C；A 补测自己的记录时使用 A。
stage / operation：实际阶段和动作名称，例如规则编译、正式复算、独立核验、账本追加。不能把一组不同动作笼统写成“处理完毕”。
implementation_version：代码版本或文件摘要。rule_version / replay_id / verifier_version 按适用情况填写，不适用需说明。
input_artifact / input_sha256：本操作对应的输入和摘要；若是批量输入，给可复现的索引/清单。
claim_ids：本操作实际归属/受益的 claim ID 列表。多个 run 可能重用 c-001，要同时用 run_id 区分。
status：操作的实际成功、失败或其他明确状态；失败仍保留测量。
started_at / finished_at：带时区的时间，方便追溯；duration_ms 用实际计时来源，不只根据日志的四舍五入时间猜测。
duration_ms：本记录计费边界内的实测耗时，单位毫秒。
measurement_boundary：说明开始到结束覆盖什么，以及是否包含模型等待、子检查、双跑或其他子操作。
model_calls / tokens_in / tokens_out：本记录范围内真实请求次数及实际用量。没有模型调用时明确 model_calls=0、tokens=0；有调用却无用量凭据时填 null 并列缺测原因。
model_event_refs：能够对应到调用记录的引用；若上游采集已经计费，注明本记录不能重复累计。
human_minutes / human_work_id：实际人工分钟和可去重的工作标识。无人工填 0；未测填 null。同一段人工工作只计一次。
aggregation_role：chargeable 表示计入本轮汇总；summary_only 表示只展示已计入子项的合计，不再重复收费。
included_operation_ids：这条总计已经包含的子操作 ID。若父子都有时长，只能在明确且不重叠的计费口径下汇总。
allocation：共享操作的 claim 分摊列表，每项 claim_id + fraction。适用时 fraction 总和为 1；单 claim 操作给它 1。
allocation_policy：说明为什么这样分摊。没有归属或没有协商清楚时保留未知，不把全部共享成本随便挂给第一条 claim。
measurement_evidence：实际日志/计时/调用用量文件的相对路径。数据不得含密钥。
missing_reasons：缺什么以及为什么；空列表只有在本记录确实完整时才表示没有缺测。
notes：双跑/重试、与其他计费记录的关系、适用范围等补充。

模板中的字段名是本轮回传建议；如果已有自己的记录格式，可原样附上并提供逐字段映射、计费边界和单位，无需为了回传修改冻结模型。

三、最终核算口径

CU = (输入 token + 输出 token) / 1000 + 耗时毫秒 / 1000 + 人工分钟 * 60。
M10 要求每条 claim 全流程 <=6 CU；平均值/p95 合格不抵消某条超标，CU 也不是人民币。
当前 A 只有 S2 调用小计，尚缺 A S3 回源/打包与 B/C 适用阶段。当前最贵一条约 4.386 CU、剩余上界约 1.614 CU，不能当成 B/C 各自拥有 1.614 CU。
纯本地计算 token 可为 0，耗时仍需记录；失败、重试、双跑、独立 verifier 与人工处理不能漏掉。
不要把父操作完整耗时与已包含的子调用耗时再次相加；不要拿并发整批墙钟时间直接代替逐条成本。
共享操作分摊后总量守恒，人工工作去重。未知量不填 0，已知小计不冒充总成本。
M11 同时累计各阶段的模型调用。A 现有 S2 每 claim 已用 2 次；后续若又调用模型，需要重新评估全流程是否仍满足 <=2，不能分模块各报 <=2。

四、用于报价拟合时再补充

说明样本对应哪个动作、规则/模型/数据版本、哪些是训练样本、哪些留作检验；预测值要保存在执行前。
本包 A 已有 capture_claim 的拟合，不能用于宣称 rewrite_rule/add_field/reverify 的报价误差已验收。
B 的 M4 用对应动作/方案的实测成本检验，并提前约定误差分母和零成本处理。
